# 추가 설정의 백업·복원 보존

## 적용 범위

백업 v2 구조를 유지하며, 기존 v1 파일도 읽는다. 저장된 설정 문자열을 그대로 옮기므로 누락값을 0으로 바꾸거나 계좌 이름으로 재원을 추측하지 않는다.

- IRP 현재 잔액 재원 구분, 혼합 재원의 금액, 인출 비율, 세율, 최초 수령연도, 종신 여부
- IRP 계좌 합산의 출발·도착 계좌와 연도
- 은퇴 목돈의 IRP 연결, 투입액, 목돈별 이연퇴직소득세율
- 개인별 세금 가정, 연도별 연금 가정, 기납부액·외국납부세액·공제
- 기존 자산 상세와 이력, 소급 시세의 수량 근거 날짜
- 기존 저장 계획·분석·초안 및 다른 설정

화면에서 아직 저장하지 않은 편집값은 포함되지 않는다. `plannerRecovery`의 복원 직전 사본, 마지막 가져오기 기록, 시세 되돌리기 자료는 해당 브라우저의 복구용이며 내보내지 않는다. 실제 시세 이력과 계산에 필요한 입력은 내보낸다.

## 사용자 흐름

1. 편집 화면에서 저장한 뒤 설정 → 내보내기(JSON)를 누른다.
2. 파일명에 생성 시각(UTC, 밀리초까지)을 넣어 같은 날 만든 백업을 구분한다. Drive도 같은 명명 규칙을 쓴다.
3. 가져오기 확인창에 파일명, 생성 시각, 자산·이력 수, IRP·세금 설정 포함 현황을 표시한다.
4. 현재 존재하는 IRP·세금 설정 경로가 백업에 없거나 자산·이력이 줄어들면 경고한다. 건수가 같아도 사람이나 연도가 다르면 누락을 감지한다.
5. 확인하면 전체 교체한다. 자동 병합은 하지 않는다. 사전 검증·미리보기 이후 변경 검사·트랜잭션·직전 사본 보관은 유지한다.
6. 설정의 ‘이 브라우저에 마지막으로 가져온 백업’에서 파일과 생성/가져오기 시각을 다시 확인한다. 이후의 편집 내용을 이 기록에 포함된 것으로 오해하지 않도록 안내한다.

UTF-8 BOM이 붙은 JSON도 파일/Drive 가져오기에서 처리한다. 기존 필드의 값을 다른 값으로 바꾸는 것까지 모두 비교하는 변경 내역 화면은 아니며, 경고가 없더라도 전체 교체 확인은 필요하다.

## 검증

- `frontend/src/lib/backupFeatures.test.ts`: v1/v2 왕복, 추가 필드 및 0/false/알 수 없는 미래 필드 보존, 미리보기 비변경, 누락 경고, 잘못된 파일 거부, 직전 복구, 가져오기 기록, 파일명, 모의 Drive API.
- `tools/check-backup-ui.cjs`: 합성 데이터가 있는 별도 Chrome 프로필에서 실제 내보내기 버튼의 파일 내용과 파일 입력 가져오기(BOM 포함)를 검증한다. 덮어쓰기 경고·새로고침 후 기록·PC/모바일 폭·왕복 전후 세금 분석 일치를 확인한다.
- 실행: `tools/wsl-dev.sh test`, `tools/wsl-dev.sh build`, Windows에서 `node tools/check-local-app.cjs --income-tax`.
- Drive 테스트는 모의 API이다. 실제 Google 계정에 파일을 업로드하거나 인증을 수행하지 않는다.

## 적용 경계

코드 수정, 별도 테스트 프로필의 가져오기, 백업 JSON 파일 생성은 사용자의 실제 브라우저 데이터 갱신과 다르다. 개인 데이터 반영 완료 판단은 정확한 입력 파일을 식별하고 대상 브라우저에서 가져온 파일을 확인한 후에만 한다. 새 파일을 확인하지 못하면 이전 원본을 최신 자료라고 간주하지 않는다.
