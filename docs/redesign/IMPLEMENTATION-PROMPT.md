# 개발 도구에 전달할 적용 작업 지시문

> 후속 개발자는 [APPLIED-REDESIGN.md](APPLIED-REDESIGN.md)와
> [09-implementation-progress.md](09-implementation-progress.md)를 먼저 읽는다.
> 현재의 월별 엔진·실제 UI·보호 장치를 보존하고, 아래 초기 작업 지시를 중복 적용하지 않는다.

아래 내용을 저장소를 수정할 개발 환경에 전달한다. 개발팀용 주 요청서는 [DEVELOPMENT-REQUEST.md](DEVELOPMENT-REQUEST.md), 상세 명세는 [05-implementation-spec.md](05-implementation-spec.md)다. 화면 참조를 위해 `docs/redesign/` 폴더 전체를 함께 전달한다. 이 파일 자체는 작업 완료 기록이 아니다.

---

이 저장소를 현재 자산 관리와 미래 은퇴설계를 함께 제공하는 도구로 보완해 주세요. `07-current-assets-and-retirement.md`를 먼저 읽고 해당 제품 목적·홈 우선순위·현황/전망 경계를 이전 설명보다 우선하세요. 은퇴 입력 없이 시세 갱신·계좌/종목 상세·평가 이력·실제 배당을 사용할 수 있어야 합니다. AM-01~AM-10 보존 목록과 C01~C29 검수, R0 현재 기능 기준선을 기존 A/B/G·R1~R6에 추가하세요. 새 주식 전문 화면이 미완성이면 기존 접근 경로를 보존하세요.

먼저 적용되는 AGENTS.md 및 프로젝트 지침을 읽고, 작업 트리의 사용자 변경을 보존하세요. `docs/redesign/05-implementation-spec.md`를 통합 기준으로 사용하고, `01-current-review.md`의 근거, `02-domain-and-engine.md`의 계산 계약, `03-experience-design.md`의 UX, `04-delivery-and-acceptance.md`의 A01~A30을 함께 확인하세요. 추가 인수 기준은 05의 B01~B24와 G01~G06입니다.

이번 목표는 재건축 전용 도구가 아닙니다. 재건축 없는 사람, 부동산 없는 사람, 일반 자가·임대·임차인, 1인 가구, 이미 은퇴한 사람에게 맞는 화면과 계산이 나와야 합니다. 사용자 유형을 강제 선택시키지 말고 실제 데이터와 명시적으로 확인한 없음/미입력 상태에서 기능 적용 여부를 결정하세요.

구현 순서는 07의 R0 기준선 이후 05의 R1~R6입니다. R1의 국민연금 중복, 저장 시 보유세 설정 유실, 잔액 초과 지급, 법인 배당 세금 중복을 코드와 재현 사례로 확인한 뒤 수정하세요. 지급액을 제한하면 계좌 표뿐 아니라 현금흐름 수입에도 같은 실제 지급액을 사용해야 합니다. 기존 테스트가 잘못된 식을 정답으로 고정하고 있는지도 검토하세요.

이후 공통 원천·기능 노출(R2), 부동산 없는 사용자도 완결되는 월별 은퇴 원장(R3), 일반 부동산·재건축·부채 사건(R4), 화면·비교(R5), 이전·복원·전환(R6)을 적용하세요. 한 단계의 코드·테스트·데이터 호환성을 함께 완성하고, 미지원 범위를 조용히 0으로 처리하지 마세요.

필수 원칙:

- React·TypeScript·Dexie·PWA를 유지하고 기존 데이터·이력을 보존합니다.
- 미입력, 해당 없음, 확정 0, 조회 실패를 구분합니다.
- 같은 경제적 자산·현금·세금을 중복 집계하지 않습니다.
- 수입·계좌 잔액·세금·상세 화면은 같은 run과 입력 revision을 사용합니다.
- 미래 사건·실제 발생·과세 판단·납부 시점을 분리합니다.
- 재건축 없는 사용자에게 준공·분담금·준공 지연안을 노출하지 않습니다.
- 개인정보나 주소·금액을 외부 서비스에 전송하지 않습니다.
- 현재 요청자의 선호는 추가 설치 없이 진행하는 것입니다. 기존 도구로 가능한 작업을 수행하고, 의존성 설치·환경 변경이 꼭 필요할 때는 그 필요와 범위를 설명해 별도 승인을 받습니다.
- 원격 push·배포·실제 개인 데이터 이전은 별도 요청 없이 실행하지 않습니다. 로컬 코드와 이전 미리보기·검증을 먼저 완성합니다.

전체 페이지는 `DEVELOPMENT-REQUEST.md`의 대응표와 `full-app.html`을 기준으로 구현하세요. `screenshots.html`은 화면 이미지 모음이며, `06-full-app-walkthrough.md`에 실제 동작과 한계가 있습니다. 홈·자산·계획·분석·설정·상세·연금·법인까지 실제 데이터와 연결해야 하며, 별도 데모 페이지만 추가해서 완료 처리하지 마세요.

`full-app.html`은 합성 데이터로 동작하는 UX 시제품입니다. 고정 기간·수동 세금·메모리 저장·단순 법인 계산은 제품 구현이 아닙니다. 제품에는 명세의 날짜·계산·영구 저장·복원 계약을 구현하세요. 예전 `prototype.html`은 분석 일부의 참고 자료입니다. 시제품 계산식을 제품 엔진으로 복사하지 마세요. `verify-baseline.cjs`는 기준 커밋의 결함 관찰용 스크립트이며, 결함 수정 후에도 그대로 통과해야 하는 정답 테스트가 아닙니다.

작업 결과에는 완료한 R 묶음, 변경 파일, 실제로 실행한 검사와 결과, 미실행 검사, 데이터 영향, 남은 적용 항목을 기록하세요. 단순히 문서만 다시 요약하지 말고 현재 단계의 구현을 수행하세요.
