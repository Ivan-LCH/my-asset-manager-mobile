# IRP 재원 플래그·계좌 합산·자동 인출

2026-09-17. 19번 문서의 수동 인출 비율을 기본 입력으로 쓰는 방식을 보완한다.

## 입력과 사용 순서

분석 → 개인투자시뮬 → 세금 추가정보 → IRP·사적연금의 인출 재원 확인.

1. 현재 IRP별 재원 구분을 확인한다. 계좌명 또는 기존 `taxType: irp`만으로 퇴직금 여부를 추정하지 않는다.
   - 전액 퇴직금 원금: 현재 평가액 전체가 이연퇴직소득이고 별도 운용수익이 없다고 확인한 경우.
   - 전액 세액공제 받은 개인납입금·운용수익.
   - 전액 세액공제 받지 않은 원금.
   - 혼합: 현재 잔액 중 퇴직금 원금과 과세제외 금액을 **원 단위**로 입력. 나머지가 개인납입금·운용수익. 두 금액 모두 입력해야 하며, 확인된 해당 없음은 0. 합계가 연결 잔액을 넘거나 누락되면 미확정.
   - 미확인: 기존 자료 보존. 전액 퇴직금이나 전액 비과세로 자동 지정하지 않는다.
2. 예정 퇴직금은 기존 목돈 입력의 `taxKind: severance`와 IRP 분배 금액·대상 계좌를 재사용한다. 현재 재원 금액에 미래 4.5억을 중복 입력하지 않는다.
3. 추가 퇴직금의 국세 기준 이연퇴직소득세율은 목돈 분배 카드에서 별도 입력한다. 기존 계좌의 세율을 복사하지 않는다. 미확인 세금은 확정 합계에서 제외한다.
4. 실제 합칠 계획이 있을 때만 출발 IRP에서 목적 IRP·연도를 선택한다. 자동으로 모든 IRP를 합치지 않는다. 상단 저장으로 저장한다.

현재 자산·가격 관리 화면의 잔액은 변경하지 않는다. 합산은 미래 전망 시나리오이며 금융기관에 실제 이체 요청을 보내지 않는다.

## 데이터와 계산

- 기존 `PensionTaxType`은 유지. `incomeTaxSettings.sources[id]`에 `fundingKind`, `retirementPrincipal`, `exemptPrincipal`을 확장한다.
- `PensionAllocation.irpRetirementTaxRate`는 해당 목돈의 세율이다.
- `PensionSimPlan.irpTransfers`는 출발/목적 원천 ID와 연도이다.
- 기존 백업 필드는 삭제하지 않으며, 신규 필드 미입력은 미확인이다. 기존 수동 인출 비율은 고급 항목에 보존한다.
- 같은 계좌의 연금 원천이 여러 개면 잔액과 재원을 한 번만 잡고 실제 지급 요청 비중으로 배분한다. 서로 모순되는 재원·명의 설정은 미확정으로 처리한다.
- 한 해 처리 순서: 외부 목돈 입금 → 내부 계좌 합산 → 지급 → 운용 변동. 합산은 원천별 재원과 세율을 보존하며, 외부 입금·소득으로 중복 계상하지 않는다.
- 합산 이후 출발 계좌의 지급은 중단하고 목적 계좌의 기존 지급 비율을 합산 잔액에 적용한다. 등록 지급액이 없으면 기존 남은 기간 분할 방식을 사용한다. 이는 지급 전망 가정이지 금융기관의 지급 확약이 아니다.
- 실제 인출 재원은 과세제외 → 이연퇴직소득 → 세액공제 받은 개인납입/수익 순서로 산출한다. 잔액 구성비를 전체 지급액에 곱하지 않는다.
- 같은 이연퇴직소득 범주의 복수 유입분은 각 잔액 비례로 인출하는 **추정**이다. 각 유입의 세율과 수령연차를 보존한다.
- 연간 인출 재원은 공통 원장에 저장하여 종합세금 계산과 지급 상세가 같은 값을 사용한다. 연도별 원장에는 내부이전 입출금·기말 재원도 표시한다.
- 자동 원장 활성화 시 과거 수동 인출 비율/연도별 비율보다 원장이 우선한다. 기본 재원 세율·첫 수령연도는 원천 설정을 사용한다. 연도별 세무 가정 화면에서 바꾼 비율/세율로 자동 원장을 덮어쓰지 않는다.

## 안전한 제한

- 다른 명의, 동일 물리 계좌, 출발 계좌 중복, 삭제된 연결, 과거 연도, 연쇄/순환 합산은 실행하지 않고 경고한다. 여러 출발 계좌를 한 목적 계좌에 합치는 것은 지원한다.
- 합산 뒤 옛 계좌로 예정된 목돈은 목적 계좌로 전달한다.
- 미확인 재원이 섞이면 인출 순서를 확정할 수 없어 해당 계좌 인출 세금을 미확정으로 둔다. 미확인 잔액을 편의상 비과세로 보지 않는다.
- 양의 운용수익은 개인납입/수익 재원이다. 운용손실 이후 세무원금 조정은 자동 확정하지 않고 남은 재원을 미확정 처리한다.
- 현재 잔액은 조회 시점의 자산 평가액이다. 혼합 재원 금액은 현재 잔액 기준이므로 신규 납입·실제 인출·손실 등으로 재원이 바뀌면 금융기관 내역으로 갱신해야 한다.
- 정상 연금수령·연속 수령을 가정한다. 실제 금융기관 이체 요건, 수령한도/연금외수령, 중단 연도의 수령연차, 복수 퇴직금 원천징수 정산은 별도 확인 대상이다. 본 기능은 세무 신고 엔진이 아니다.

## 확인 근거와 테스트

국세청의 [연금계좌 인출순서·계좌 이체 안내](https://t.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7885&mi=6605)를 기준으로 재원 구분과 순차 인출을 설계했다.

`pensionFunding.test.ts`: 순차 인출, 혼합 재원 누락/0, 운용수익/손실, 4.5억 추가 및 합산의 자산 보존, 출발 지급 중단, 원천별 세율, 미확인 세금, 명의/연결/순환 검증, 합산 후 추가 입금, 조회 구간 일관성, 기존 비율 호환.

`tools/check-local-app.cjs --income-tax`: 재원 플래그 저장·백업 복원·통합 세금·모바일/데스크톱 회귀.
