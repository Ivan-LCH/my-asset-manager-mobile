# 08. 개정 2 교차 점검 결과

작성일: 2026-09-14  
대상: 현재 자산 관리 + 미래 은퇴설계 개편 문서와 독립 시제품. 실제 앱 적용 완료 검수가 아니다.

## 결론

**두 목적을 함께 제공하는 방향은 타당하다.** 다만 최초 개정안에도 기존 기능 누락과 데이터 계약의 모호함, 시제품 동작 오류가 있어 개발 인계 전에 보완했다. ‘기존 기능 유지’라는 포괄 문구만으로 보존을 보장하지 않고 기능별 대응표와 검수 기준을 적용한다.

## 점검 방식

세 독립 검토자가 각각 (1) 기존 자산 기능과 개편 명세, (2) 현재 기록·미래 스냅샷·계산 경계, (3) UX·시제품·테스트 공백을 점검했다. 주 담당자가 소스 근거와 재현을 확인하고 문서/시제품 수정 및 회귀 검사를 수행했다. 검토 중에는 실제 계좌·개인 자료·외부 시세에 접속하지 않았다.

## 발견 내용과 반영

| ID | 발견 사항 | 조치·추가 검수 |
|---|---|---|
| CR01 | ‘모든 화면 같은 revision’이 과거 계획 고정과 충돌 | 현재 `assetRevision`과 선택 전망 `snapshot/run` 분리. 홈에서 두 기준 표시. 개발 요청서·02·05·07 계약 정리 |
| CR02 | 계좌 총액과 일부 종목 합계 중 무엇을 쓸지 불명확 | 평가 모드·포함 범위·계좌 현금·미분류 잔액·차이 대사 명시. 100만=80만+20만 정답과 C22 |
| CR03 | 과거 기준일/정정 시점·외화 원자료의 정밀도 부족 | `effectiveAt/recordedAt`, 월중 시작 경계·배당 재계상 방지, 원통화 Decimal 보존. C24/C25 |
| CR04 | 기존 Google Drive 백업이 유지 목록에서 누락 | AM-10에 로그인·폴더·저장·목록·복원·로그아웃과 인증실패 검수 추가. C21. 실제 전송 승인은 별개 |
| CR05 | 시세 요청 중 수량 수정·매각·삭제 및 응답 순서 역전 누락 | 가격과 보유 수정 명령 분리, 요청/보유 버전·관측시각 검증. C23 |
| CR06 | 환율 편집 UI를 기존 기능처럼 표현, 일간 가격 등락·비주식 상세 이전 기준 부족 | 환율 데이터 보존과 신규 UI 구분, AM-04/09/10 구체화. 단가 등락·과거 수량 정정·연금형 원자료 C27~C29 |
| CR07 | 배당 기록 추가/삭제 시 현금 처리 의미가 모호 | 기본은 실적 기록만 변경, 현금 자동 입출금 없음. 후속 현금 연결은 별도 확인/거래 ID 필요 |
| CR08 | 준공 지연 선택 후 자산 현금 상세가 기본안으로 돌아감 | `assetFlows()`에 선택 시나리오 적용, 제목에 시나리오 표시. 2033 지연안에 임대료 없음 회귀 검사 |
| CR09 | 계획 미입력 예시에서 기본 급여·생활비·세금·은퇴 사건 표시 | 미입력 계획/가정은 안내로 대체, 미입력 은퇴 사건 생성 금지. 설정에도 미입력 표시·독립 가구 버튼 적용. 실제 자산/사용자 사건은 유지 |
| CR10 | 자산 명의 설정이 은퇴계획 배우자 토글에 종속 | 독립 가구·명의 설정 추가, 은퇴 미입력 배우자 계좌 등록 검사. 제품 계약 C26 |
| CR11 | ‘전체 자산’ 복귀 시 주식 필터가 남음 | 필터를 URL로 결정, 실제 칩 이동→전체 복귀 회귀 검사 |

CR01~CR07은 **실제 제품 개발 요구와 검수 기준을 보강한 것**이다. 실제 앱 코드를 수정한 것으로 해석하면 안 된다. CR08~CR11은 **독립 시제품에서 수정**하고 회귀 검사에 포함했다.

## 검증과 남은 범위

실행 결과는 [06의 개정 2 확인 기록](06-full-app-walkthrough.md)에 기록한다. 검사 스크립트는 [계산 경계/참조 검사](check-current-assets.cjs), [브라우저 검사](check-full-app.cjs)다.

시제품은 가상 시세, 단순 원장, 메모리 저장을 사용한다. 실제 시세 비동기 충돌, Google 인증, 실제 배당 CRUD, 계좌 대사·외화·과거 스냅샷 저장, 데이터 이전, 세무 정확성은 제품 구현 환경에서 AM/C 및 기존 A/B/G 기준으로 별도 검증해야 한다. 이 교차 점검이 모든 결함의 부재나 세무 정확성을 보증하지 않는다.

개발 전달 시 [요청서](DEVELOPMENT-REQUEST.md) → [07 개정안](07-current-assets-and-retirement.md) → [05 구현 계약](05-implementation-spec.md) 순으로 읽고, R0 기준선부터 적용한다. 시제품이 생략한 기존 전문 기능을 제품에서도 삭제하지 않는다.
