# 16. 퇴직금 → 기존 IRP → 연금 재산정 연결

적용일: 2026-09-16. 15번 문서의 목돈 IRP 별도 인출 방식과 연금 연동 건강보험 설명은 이 문서로 대체한다. 실제 사용자 자료·금액을 문서나 테스트 픽스처에 저장하지 않는다.

## 확인된 문제와 수정

| AS-IS | TO-BE |
|---|---|
| IRP 배분 금액을 별도 가상 계좌로 만들어 전역 잔여 기간으로 인출 | 기존 IRP 원천을 참조해 같은 계좌에 입금하고 월수령액 재산정 |
| 추가 지급은 모두 남편에게 귀속 | 연결한 IRP의 명의 유지 |
| 화면은 30년 고정, 실제 백업은 다른 기간 | 저장된 기본 수령 기간을 표시·편집. 개별 시작·종료 연도가 우선 |
| 미래 입금 전액을 현재 원금 요약에 선반영 | 선택 연도 계좌 원장의 기말 잔액 표시 |
| 총 연금만 보여 금액의 출처를 찾기 어려움 | 연금별 월·연 지급, 입금 전후 잔액, 재산정 산식, 계좌 원장 상세 |
| IRP 지급·사적연금을 공적연금처럼 건강보험 소득에 포함 | 연금 연동 모드에서 공적연금과 사적연금·계좌 인출 분리 |
| 부부 각각 지역보험료 산출 후 무조건 합산 | 같은 지역가입 세대/별도 지역가입 세대 가정으로 구분 |
| 재산 점수표 상한을 하한처럼 사용, 1,041점 누락 | 60등급 전체 경계 수정 및 각 경계 회귀 검사 |

추가 자금에 따른 연금 증가 자체가 중복은 아니다. 기존 월수령액에 추가 자금을 반영하지 않고, 별도의 숨은 기간으로 추가 지급을 만드는 방식이 문제였다. 기존 지급액은 원본 입력에 그대로 보존한다.

## 사용 순서

1. **분석 → 세부 계산·고급 기능 → 연금 시뮬레이션 → 목돈 분배**.
2. IRP로 배분된 목돈에 **합산할 퇴직IRP**를 선택하고 저장한다. IRP 후보가 하나뿐이면 자동 연결임을 표시한다. 여러 후보를 자산명·잔액 크기로 임의 선택하지 않는다.
3. **과세·수령 기준**에서 기존 수령 기간과 건강보험 가입 가정을 확인한다. 가입 형태 미입력은 같은 지역가입 세대라는 미확인 가정으로 표시한다.
4. **분석 요약 → 월 수입 → 연금별 월수령액·추가 입금 근거**에서 원천별 지급과 계산 근거를 확인한다. 계좌 잔액·지급 내역의 연도를 누르면 계좌별 보존식도 확인한다.

새 계획이나 새 자산을 복제할 필요가 없다. 실제 브라우저의 연결 대상·가입 형태를 에이전트가 임의로 저장하지 않는다. 원본 백업은 그대로 가져올 수 있고, 새 연결 필드는 내보내기·가져오기에 보존된다.

## 계산 계약

- `PensionAllocation.irpSourceId`가 기존 연금 원천을 가리킨다. 연금의 `linkedStockId`가 주식 계좌를 가리키면 그 실제 계좌 잔액에 연결한다. 계좌명과 종목 ID를 모두 해석하되 원금은 한 번만 합산한다.
- 등록 월수령액이 있고 입금 직전 예상 잔액이 양수이면 **기존 월수령액 × (입금 전 잔액 + 입금액) ÷ 입금 전 잔액**으로 재산정한다. 이후 같은 금액을 다시 확대하지 않으며 저장된 지급액 증가율과 잔액 한도를 적용한다.
- 가상 예: 운용수익 0, 최초 수령 연도 입금, 기존 잔액 3억·월수령 165만·추가 입금 4.5억이면 합산 7.5억, 월 412.5만이다. 실제 사용자의 예측액을 고정한 값이 아니다.
- 미래 입금 직전 잔액은 현재 평가액에 그때까지의 운용·지급을 반영한 값이다. 수익률이 저장되어 있으면 단순히 현재 잔액에 입금액만 더한 비례 예시와 실제 결과가 다르다.
- 등록 월수령액이 없거나 잔액이 소진되어 비율을 산정할 수 없으면 예상 합산 잔액을 해당 원천의 남은 기간으로 나눈다. 이 대체 계산은 상세와 안내에 명시한다.
- 동일 계좌에 같은 해 여러 입금은 먼저 합산한다. 같은 계좌를 여러 연금 원천이 공유하면 기존 요청 비율을 유지하며 가용 잔액까지만 지급한다.
- 수령 종료 후 입금은 잔액에 보존하지만 기간을 임의 연장하지 않는다. 과거 입금은 현재 잔액·등록 지급액에 이미 반영된 것으로 보며 다시 추가하지 않는다.
- 연결이 없거나 삭제·처분된 경우 원금은 **IRP 연결 대기**로 보존하고 추가 지급·운용수익은 미산정으로 표시한다. 수입을 확정한 결과로 오해하지 않도록 요약에서 경고를 펼친다.
- 목돈의 투자 배분은 현금 수입에서 제외하며, 실제 계좌 인출만 연금 수입에 반영한다. 동일 지급 원장이 요약·연도별 현금흐름·연금 상세·세금 입력을 공급한다.
- 연 단위의 연초 입금·지급 후 잔액 운용 가정이다. 금융기관의 실제 연금 지급 공식, 세법상 연금수령한도, 수수료·수익률 경로를 확정한 모형은 아니다. 비례 확대는 추가 입금 시 재설정하는 계획 가정이며 고정 비율 인출을 매년 새로 계산하는 모형이 아니다.

## 건강보험 보완 범위

이번에 사용자가 확인한 **연금 시뮬 연동 모드**의 요약·연도별 현금흐름·연금 상세에 같은 연도별 건강보험 모형을 적용했다.

- 공적연금 지급액의 50%, 개인별 연 1천만 원을 초과한 금융소득 전액, 저장된 기타소득(남편 귀속, 전액 반영 가정)을 사용한다. IRP·사적연금 지급은 별도로 보여주고 건강보험 소득에서는 제외하는 정책 가정이다. 원금 입금·인출을 배당이나 이자소득으로 다시 생성하지 않는다.
- 같은 지역가입 세대이면 부부 재산 과표를 합산한 뒤 1억 공제를 한 번 적용한다. 별도 세대 선택 시 각각 계산한다. 합산 모드에서는 개별 고지액처럼 남편·아내 보험료를 표시하지 않는다.
- 2026 요율 7.19%, 점수당 211.5원, 장기요양 0.9448%/7.19%, 소득최저보험료 20,160원과 건강보험 월 상한 4,591,740원을 사용하는 전망이다. 소득최저보험료를 적용한 후 재산분을 더한다. 자동차는 이 모형에서 부과하지 않는다.
- 과세표준은 여전히 기존 부동산 시점·시가 × 75% × 60%의 추정이다. 주택 특례, 실제 공시가격, 토지·상가, 주택부채 공제, 지역 감면, 직장가입·피부양자, 실제 소득·재산 반영 시차는 구현하지 않았다. 2031년 법령을 예측·확정한 것이 아니다.
- **기본 등록 자산 모드의 수동 건보 입력과 법인 모드의 직장 건보는 이 새 세대 모형으로 일괄 교체하지 않았다.** 설정을 임의 변경하지 않으며 해당 모드의 기존 간이 모형 한계를 유지한다. 새로운 지역가입 모형과 혼용해 확정 납부액으로 해석하면 안 된다.
- 기존 연금소득세·금융소득세 간이 산식 전체를 재설계한 작업은 아니다. 지급액 연결과 건강보험 문제를 고쳤다고 실제 세무 정확성을 보증하지 않는다.

## 검증

### 건강보험 요약 표시 후속 보완 (2026-09-16)

- 건강보험을 펼치기 전에도 선택 연도의 월 예상액을 원 단위로 표시한다. 현금흐름의 `healthInsuranceMonthly`를 그대로 사용한다.
- 같은 지역가입 세대의 생활비 반영액은 세대 합산액이다. 상세에서는 별도 지역가입 세대라고 각각 계산한 남편·아내 참고액과 그 합계를 비교한다. 참고액은 실제 개인 고지액이나 합산 보험료의 배분액이 아니며 생활비에 추가하지 않는다.
- 별도 지역가입 세대는 접힌 상태에서 총액과 남편·아내 월 금액을 함께 표시한다. 상세에서도 각 세대의 장기요양 포함 월 합계를 표시한다.
- 가입 형태가 저장되지 않았으면 접힌 상태에도 `가입 형태 미확인 · 같은 지역가입 세대로 합산 가정`을 표시한다. 실제 가입 설정을 임의 확정하거나 변경하지 않는다.
- 지역가입자는 세대 단위로 산정하며, 직장가입자는 별도 기준이다. 가족이라는 이유만으로 모두 합산하는 것은 아니다. [국민건강보험법 제69조 제4·5항](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031509403).
- 이번 후속 보완은 표시·설명 변경이며, 보험료 계산식이나 가입 자격 모형을 추가 변경하지 않았다.
- 개인별 참고액은 선택 연도의 소득분·재산분·장기요양으로 구분한다. 세대 합산은 재산 공제 1억 원을 한 번 적용하지만 별도 세대 계산은 각각 공제하므로 두 계산이 다를 수 있음을 설명한다. 실제 금융정보나 특정 연도 금액을 하드코딩하지 않는다.
- 분석 요약에서는 월 총액을 접힌 제목에 한 번만 출력한다. 상세의 반복 총액을 제거하고, 별도 세대 모드의 개인별 월 총액도 요약과 상세에서 중복하지 않는다. 단독으로 표시하는 연금 시뮬레이션 화면은 총액을 유지한다.
- 부동산 추정 과표(시가 × 75% × 60%), IRP 원금 입금·인출 처리, 공사 중 토지 과표 미반영에 따른 과소 산정 가능성을 상세에 명시한다.
- 후속 검증: 타입 검사와 실제 브라우저 분석 회귀 검사 통과. 가상 데이터로 PC(1440px)·모바일(390px)의 접힌 금액, 가입 미확인/합산/별도 표시, 개인 금액 합계와 상세 총액 일치, 2031→2032 연도 전환, 열람 전후 원본 불변을 확인했다. 모바일 스크린샷도 직접 확인했다.

### 기존 계산·연동 검증

- `irpLink.test.ts`: 같은 계좌 합산, 추가 수령액, 기존 소액 계좌 불변, 입금 시점, 성장 잔액, 이미 수령 중 입금, 동년 복수 입금, 공유 계좌, 명의, 연결 누락·삭제, 0원·미등록 지급액, 종료 후 입금, 과거 입금, 미연동.
- `annualHealth.test.ts`: 재산 60등급 전체 경계, 공적연금/IRP 소득 구분, 금융소득 개인별 문턱, 세대 공제, 가입 가정 미확인, 최저·상한.
- `check-irp-link.cjs`: 가상 자산으로 실제 연결 선택·저장, 백업 왕복, 월수령액과 계산 근거, 계좌 상세, PC·모바일 너비, 열람 전후 원본 불변.
- 2026-09-16 전체 단위 테스트 **209개 / 16개 파일 통과**. 타입 검사·최종 배포 빌드·배포본 브라우저 실행 검사 통과. 실제 브라우저의 IRP 선택·저장·백업 왕복·수령액 근거·건보 근거와 PC/모바일 너비 검사를 통과했다.
- 기존 주식·자산 관리, 시세 성공/실패 모의 응답, 수량·취득가·배당 보존, 고급 계획 저장/재열람 회귀 검사도 통과했다. 실제 외부 시세 공급자·Google 인증까지 검증했다는 뜻은 아니다.
- 실제 백업은 메모리에서만 연결안을 재현해 원본 불변과 연도별 잔액 보존식을 확인했다. 실제 사용자 브라우저 설정은 변경하지 않았다. 실제 금융정보는 테스트 코드·문서·스크린샷·외부 요청에 넣지 않는다.
