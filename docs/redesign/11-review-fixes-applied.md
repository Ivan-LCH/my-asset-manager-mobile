# 11. 실제 데이터 검증에서 발견한 8건 보완 적용

2026-09-15. [10번 검증 보고](10-imported-data-ui-review.md)의 8개 항목을 실제 앱에 반영했다.
이 문서는 이번 보완의 적용 결과다. 전체 세법·외부 시세 공급자·실기기 PWA까지 검증했다는 뜻은 아니다.

## 연금 출금 연결 계약

- `Flow.assetId`와 `amountSource`는 **등록 지급액을 읽는 원천**이다.
- `withdrawalAssetIds`는 **실제로 잔액을 줄일 자산 ID의 순서 있는 목록**이다.
  `withdrawalAccountAssetId`는 선택한 계좌의 기존 구성원 ID를 기준으로 계좌 구성을 확인한다.
- 지급 목표를 목록 순서대로 나누어 실제 잔액까지만 인출한다. 남은 목표는 한 번만 미충족으로 기록한다.
  원천세는 실제 실행한 인출액에만 적용한다. 연금 기록에 주식 원금을 복사하지 않는다.
- 제외/중복 연결된 종목은 출금 후보에서 제외한다. 없는 ID·중복 ID·출금 불가 역할·계좌 구성 변경은
  재검토를 요구한다. 새 종목이 추가됐다고 출금 권한을 자동 확대하지 않는다.
- ‘계좌별 묶음’은 원본 기록의 보기/출금 연결이다. 새로운 금융 계좌 잔액을 만들어 종목과 이중 합산하지 않는다.
- 계좌 탐색은 이름 대신 구성원 자산 ID로 연결하므로 이름 변경을 따라간다. 기준 구성원이 삭제되거나
  다른 계좌로 이동한 경우에는 원본 계좌 구성을 다시 확인해야 한다. 금융기관 계좌 자동 동기화는 아니다.
- 계산 버전은 `monthly-ledger-3`이다. 기존 저장 분석은 그대로 보관되며 새 버전으로 덮어쓰지 않는다.

## 이미 가져오기를 했다면

원본 파일을 다시 가져올 필요 없이 로컬 앱을 새로고침한다. 설치형 PWA에서 업데이트 안내가 나오면
미저장 입력을 저장한 뒤 업데이트한다. 이번 작업이 사용자의 평소 브라우저 저장소를 변경한 것은 아니다.

1. **자산 → 전체 → 주식 계좌 → 종목** 순서로 확인한다. 계좌 선택 상태에서 새로고침해도 유지된다.
2. **계획 → 기본·확인**에서 원본 복원 상태와 연결 대기 항목을 확인한다. 기존 입력 복사는 초안이며,
   가구/명의·은퇴 월일·여행·보험·법인 조건이 자동 확정되는 것은 아니다.
3. **자산 연결**에서 계좌/유형을 선택하고 필요한 자산만 연다. 일괄 채우기는 빈 가격 상승률/배당률만
   대상으로 하며, 기존 개별 값·세율·명의·확인 상태를 보존한다.
4. **연금 상세 → 이 연금의 지급 계획 연결**에서 지정 원본만 연결한다. 정기 입출금의 실제 출금 계좌,
   종목 목록/순서, 날짜, 원천징수 가정을 확인한다. 이미 옛 방식으로 연결한 항목도 이 출금 계좌를
   다시 선택하면 기존 지급액 원천과 실제 출금 목록을 분리할 수 있다.
5. 확인한 계획을 저장해 **새 분석**을 만든다. 과거 저장 분석을 볼 때는 당시 조건/계산 버전을 확인한다.

## 검증과 개인정보 처리

- 단위/회귀: **11개 파일, 154개 테스트 통과**. 계좌 그룹·로컬 복귀 주소·연결 지급 원천,
  합산 잔액 소진·실지급 세금·중복/누락 차단·계좌 구성 변경·가구 초안 보존을 추가했다.
- 최종 TypeScript/Vite/PWA 빌드 성공(`logs/backup-compat-build.out.log`, 종료 코드 0).
  최대 앱 JS 청크는 433.55 kB다. 실제 제품 빌드의 브라우저 실행도 `PRODUCTION_SMOKE=PASS`로 확인했다.
- 실제 이전 백업: 원본 모든 테이블과 복원/재내보내기/v2 재복원을 대조했다. 기존 자산/이력/설정은 같았다.
- 실제 데이터 브라우저: **21개 경로 × PC/모바일**, 직접 상세 5개 유형, 주식 배당, 계좌 재접속,
  선택 연금 연결·저장, 단일 자산 편집 폼을 확인했다. 개인정보 화면 캡처는 만들지 않았다.
- 합성 데이터 브라우저: 시세 모의 성공/실패, 수량/원가/배당 보존, 계획 저장/재조회, 불변 분석,
  지연 시나리오와 고정 비용, 백업 원자적 거절 및 모바일 주요 화면 검사를 통과했다.
- 실제 파일 검사의 UI/원본 보존 검사는 통과했다. Windows에서 일부 임시 Chrome 파일을 Node가
  삭제하지 못해, 종료된 테스트 프로필만 경로/사용 여부 확인 후 PowerShell로 정리했다.
  향후 검사 도구에도 이 정리 경로를 추가했다. 원본 백업과 실제 브라우저는 그대로 둔다.
- 문서/소스 ZIP에는 개인 백업과 개인 화면 캡처를 포함하지 않는다. 갤러리 이미지는 합성 데이터다.

재현 명령(실제 파일 경로는 사용자가 지정):

```powershell
powershell -NoProfile -File .\tools\wsl-dev.ps1 -Action test
powershell -NoProfile -File .\tools\wsl-dev.ps1 -Action build
node tools/check-backup-compat.cjs <백업경로> --audit
node tools/check-local-app.cjs --backup <백업경로> --review --expect-fixed
node tools/check-local-app.cjs
node tools/check-local-app.cjs --production
```

세금은 여전히 기간별 사용자 예상액이며 전체 법령 자동 계산이 아니다. 실제 시세 공급자·Google 로그인·
실기기 설치/업데이트·사용자의 모든 입력 조합은 별도 인수 범위다. 원격 Git push/배포는 하지 않았다.
