# 03. 화면과 사용 흐름

개정 2: 현재 자산 관리는 독립된 핵심 사용 흐름이다. [07](07-current-assets-and-retirement.md)의 홈·주식 전문 화면·최초 사용 및 현황/전망 경계를 우선한다.

추가 적용 기준: [05의 사용자별 기능 노출 규칙과 전체 화면 수정안](05-implementation-spec.md)을 우선한다. 재건축 기능은 해당 자산/계획이 있을 때만 표시한다. 미입력과 없음 확인을 구분하고, 기본 은퇴 화면은 부동산 없는 사용자에게도 완결되어야 한다.

## 1. 정보 구조

하단 탭은 **홈 · 자산 · 계획 · 분석**으로 구성하고 설정은 홈 상단으로 이동한다. 기존 4개 하단 탭의 모바일 구조는 재사용하되, ‘분석’ 안에 숨겨져 있던 입력을 ‘계획’으로 옮긴다.

| 화면 | 사용자의 질문 | 기본 내용 |
|---|---|---|
| 홈 | 지금 내 자산은 어떻고 앞으로는 어떤가? | 현재 자산·부채·순자산·구성·갱신 상태 우선, 별도 은퇴 전망과 일정 |
| 자산 | 무엇을 얼마나 보유하고 어떻게 변했나? | 유형별 전문 관리, 주식 시세·계좌·종목·평가 이력·실제 배당, 부채·명의·기준일 |
| 계획 | 앞으로 무엇이 언제 바뀌는가? | 사람별 은퇴일, 생활비 구간, 사건 타임라인, 임대·대출·퇴직금, 가정 |
| 분석 | 생활이 가능한가, 왜 그런가, 무엇을 바꿀까? | 세후 수지·기말 현금·최초 부족월, 연도/월 상세, 시나리오 비교 |

법인·고급 연금 전략은 분석의 ‘고급 비교’에 둔다. 기본 계산은 별도의 ‘연동함’ 토글 없이 원천 데이터를 사용한다. 고급 비교는 기본 원천을 수정하지 않는다.

## 2. 최초 사용

1. ‘자산부터 관리’, ‘은퇴계획 시작’, ‘예시 둘러보기’를 구분한다. 자산 관리만 선택하면 아래 은퇴 입력 과정은 건너뛴다. 샘플을 실제 자산에 자동 삽입하지 않는다.
2. 본인·배우자/가구원, 예상 은퇴 시점, 원하는 생활비를 입력한다. 미정은 미정으로 저장한다.
3. 현재 현금·예금, 부동산과 부채, 투자 계좌, 연금 지급권 순서로 추가한다. 모두 입력할 때까지 분석을 막지는 않되 불완전한 항목을 표시한다.
4. 은퇴·재건축·목돈 수령 등 가까운 큰 사건을 확인한다.
5. ‘입력 기준 첫 전망’을 보여주고, 결과를 가장 크게 바꿀 미확인 정보부터 안내한다.

주소나 세무 상세를 처음부터 모두 요구하지 않는다. 해당 계산을 활성화할 때 필요한 정보를 요청한다. 모르는 공시가격에 시가의 특정 비율을 조용히 넣지 않는다. 사용자가 추정을 선택하면 비율·기준일·영향 범위를 표시한다.

## 3. 자산 상세

자산 카드는 ‘평가액’만 강조하지 않고 ‘현재 상태 / 부채 차감액 / 현금화 조건 / 다음 사건’을 보여준다. 재건축이면 ‘공사 중 · 준공 예상 2030.09 · 추가 납부 예정 5,000만’처럼 읽힌다.

부동산 상세는 기본정보, 일정, 수입·비용, 세금 자료로 구성한다. 입력에는 소유 여부·실거주·임대인/임차인 역할을 분리한다. 저장 직전에 ‘이 변경은 임대 수입 시작과 2031년 이후 세금 판정에 영향을 줍니다’처럼 엔진 의존 관계에서 생성한 요약을 보여준다.

연금은 ‘받을 권리’와 ‘현재 계좌 잔액’을 구분한다. 국민연금 예상 월수령액을 입력할 때 투자계좌 평가액을 필수로 요구하지 않는다. 연금계좌에 포함된 주식은 동일 경제적 잔액임을 연결하고 두 자산에 중복 집계하지 않는다.

## 4. 분석의 기본 화면

상단에는 시나리오·분석 기준일·반영된 저장 상태를 둔다. 중요 정보가 부족하면 숫자 앞에 ‘세금 일부 미확정’ 등 한 줄을 표시한다.

처음 보이는 내용은 다음 순서다.

1. ‘2030년 은퇴 기준, 현재 가정에서 2032년 9월 첫 자금 부족’과 같은 결론. 미완성 계산이면 결론 보류.
2. 선택 연도의 세후 반복 수지 월평균, 기말 생활자금, 최초 부족월, 순자산. 각 카드에 단위와 ‘내역 보기’를 제공.
3. 인생 사건이 표시된 현금 추이. 준공·연금 개시·대출 만기·부족월을 차트에서 선택.
4. 영향이 큰 항목 3개와 시나리오 비교 진입.

‘월평균’은 실제 납부월의 현금 잔액과 다를 수 있음을 설명한다. 목돈을 월 소득으로 섞지 않는다. 12개월을 펼치면 분담금·세금 납부월에 현금이 감소하는 것을 볼 수 있다.

### 숫자에서 원천으로

```mermaid
flowchart LR
  A[세금 연 420만 선택] --> B[세목별·납부월별 구성]
  B --> C[A주택 주택분 보유세 선택]
  C --> D[과세기준일 상태·가격·명의·산식·규칙]
  D --> E[원천 입력 수정]
  E --> F[변경 전후 비교]
  F --> A
```

위 금액은 화면 설명용 예시다. 세금 상세는 총액·소득세·재산세·종부세·부가 세목·일회성 세금·원천징수 정산을 분리하고, 계산하지 못한 항목을 0원 행으로 숨기지 않는다.

모바일에서는 짧은 구성 목록은 바텀시트, 많은 근거와 편집은 전체 화면을 사용한다. 같은 창 안에 모달을 반복 중첩하지 않는다. 뒤로가기는 상세 → 해당 연도 분석으로 돌아가고, 스크롤·시나리오·선택 연도를 유지한다. 데스크톱은 오른쪽 상세 패널로 같은 내용을 보여준다.

## 5. 연도 선택과 시나리오

연도 직접 입력/선택, 이전·다음, 주요 사건 바로가기를 함께 제공한다. 20년 뒤를 보기 위해 +를 20번 누르게 하지 않는다. 선택 상태는 URL에 `scenario`, `year`, `metric`으로 표현한다. 민감한 금액이나 주소를 URL에 넣지 않는다.

비교는 기본안과 대안 1~2개를 같은 기간·물가 기준으로 나란히 본다. ‘준공 1년 지연’ 선택 시 바뀌는 계약 일정과 유지되는 고정 일정을 구분해 보여준다. 결과는 ‘누적 임대수입 감소 / 추가 거주비 / 세금 시점 이동 / 최저 현금 변화’로 설명한다. 좋은 시나리오를 자동으로 실제 계획에 덮어쓰지 않고 ‘이 안을 기본 계획으로 적용’ 동작을 제공한다.

## 6. 입력·저장·실패 상태

| 상황 | 사용자에게 보여줄 상태 | 동작 |
|---|---|---|
| 입력 도중 | 초안 저장됨 / 아직 분석에 미반영 | 잘못된 숫자를 0으로 고치지 않음 |
| 유효한 수정 | 저장 중 → 분석 갱신 중 → 반영 완료 | 같은 revision 결과로 모든 화면 갱신 |
| 저장 실패 | 저장되지 않음 · 다시 시도 | 화면과 초안 보존, 이전 결과 표시 |
| 필수 값 없음 | 계산에 필요한 정보 2건 | 해당 원천 필드로 이동 |
| 아직 지급 전 | ‘2035년 3월부터 지급’ | 0원 이유를 보여줌 |
| 지원하지 않는 세무 경우 | 계산 미지원 / 확인된 예상액 입력 | 추정 범위에서 제외됨을 합계에 표시 |
| 오프라인 | 로컬 계산 가능 / 외부 시세 기준일 | 오래된 시세를 최신처럼 표시하지 않음 |
| 데이터 복원 | 변경될 자산·계획 개수, 누락·오류 목록 | 검증 후 교체, 이전 복원 지점 유지 |

## 7. 시각·모바일 기준

본문은 충분히 읽을 수 있는 크기를 기본으로 하고 설명을 매우 작은 회색 글씨로 밀어내지 않는다. 주 숫자는 20~28px, 본문 16px를 시작점으로 실기기에서 검증한다. 입력은 원/만원 단위를 고정 표시하고 큰 금액은 ‘1억 2,000만 원’ 미리보기를 제공한다.

터치 목표는 제품 기준으로 최소 44×44 CSS px를 확보한다. 이는 특정 접근성 표준 전체를 준수했다는 선언이 아니다. 키보드 초점 표시, dialog 이름·닫기·초점 복귀, 색 외의 증감 기호, 차트의 표 대체, 확대 글꼴, safe-area, 모바일 키보드 노출 시 저장 버튼을 확인한다.

## 8. 화면 흐름 시제품

전체 페이지를 판단하려면 새로 추가한 **[전체 앱 시제품](full-app.html#/guide)**과 **[화면 이미지 모음](screenshots.html)**을 사용한다. [06의 사용 안내](06-full-app-walkthrough.md)에 전체 페이지 대응과 동작 범위를 기록했다. 아래 `prototype.html` 설명은 이전 분석 단독 시제품에 대한 기록이다.

[prototype.html](prototype.html)을 브라우저에서 열면 설치나 서버 없이 사용할 수 있다. 분석 중심으로 다음 흐름을 표현한다. 사용자 예시 선택기는 UX 검토용이며 실제 앱에 강제 사용자 유형 선택을 추가하라는 의미가 아니다.

- 금융·연금만 보유, 일반 자가, 임대 부동산, 재건축, 이미 은퇴한 1인 가구, 미입력의 6가지 예시 선택.
- 2030~2032년 선택과 각 예시에 맞는 기본안/대안 전환. 준공 지연은 재건축 예시에만 표시.
- 반복 수지·연말 현금·연간 세금 카드를 눌러 구성 확인.
- 자산에 맞는 연금 개시·대출 상환·보증금 반환·재건축 일정 확인. 예정 사건 없는 경우 사건 패널 숨김.
- 미입력 예시에서 KPI와 비교를 숨기고 정보 입력 안내. 미입력을 0원 결과로 표시하지 않음.
- 닫기·ESC·배경 클릭 후 원래 위치로 복귀.

시제품의 값은 UX 검토용 합성 자료다. 세금은 고정 예시 금액이며 세법 엔진이 아니다. 저축·인출 최적화·모든 자산 입력 화면은 구현하지 않았다. 이 시제품에서 숫자가 매끄럽게 바뀐다고 실제 앱 계산이 검증된 것은 아니다.
