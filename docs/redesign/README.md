## 제안

현재 앱을 **“현재 자산을 꾸준히 관리하고 그 기록으로 미래를 설계하는 도구”**로 발전시킨다. 시세 갱신·계좌/종목 상세·평가 이력·실제 배당은 은퇴 입력 없이 사용할 수 있어야 한다. 현재 관측과 미래 가정을 구분하면서 같은 원천으로 연결한다. React·TypeScript·IndexedDB·PWA와 기존 관리 기능은 보존하고, 분석 엔진과 데이터 계약을 단계적으로 교체한다.

현재도 자산 관리, 재건축 예상 가치, 연도별 분석, 세금 상세, 백업이 있다. 다만 같은 입력을 모듈마다 다르게 해석하는 부분이 있고, 연금 중복 합산·설정 유실·소진 후 지급처럼 은퇴 판단을 바꿀 수 있는 경로가 확인된다. 기존 기능을 더 많이 붙이기 전에 이 계산 계약부터 바로잡아야 한다.

## 먼저 결정한 방향

1. 모든 분석은 같은 입력 스냅샷·기준일·시나리오·규칙 버전에서 생성한다.
2. 자산의 현재 상태와 미래 계획을 구분한다. 준공, 입주, 임대 개시, 매각은 서로 다른 사건이다.
3. 내부 계산은 월별 현금 흐름과 날짜별 사건을 처리하고, 화면은 연도별 요약부터 보여준다.
4. 잔액과 수입을 따로 생성하지 않는다. 실제 계좌에서 지급 가능한 금액만 은퇴생활 자금에 반영한다.
5. 분석 숫자는 구성 항목 → 자산·사건 → 입력·산식·적용 규칙까지 확인할 수 있어야 한다.
6. 세금은 사실관계가 부족하면 미확정으로 남긴다. ‘0원’과 ‘계산할 수 없음’을 구분한다.
7. 기본안·준공 지연안·은퇴 연기안처럼 선택을 비교한다. 법인 설계는 고급 기능으로 분리한다.
8. 재건축 등 자산별 기능은 해당 사용자에게만 노출한다. 아직 입력하지 않은 영역과 보유하지 않음이 확인된 영역을 구분한다.

## 재건축 사례에 대한 결론

“2030년에 준공하니 모든 세금도 2030년부터”라는 단일 스위치로는 부족하다. 공사 중에도 토지 등의 과세관계를 확인해야 하고, 준공·사용승인·실제 사용·6월 1일 보유 상태·취득 관련 사건·임대 시작·납부일을 나누어야 한다. 종합부동산세는 과세기준일 현재 과세대상 주택·토지를 인별로 합산하는 구조다. 따라서 준공 전후의 **과세대상 변화**를 모델링하는 것이 맞다. [국세청 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7733&mi=2352)

예를 들어 준공을 2030년 9월에서 2031년 9월로 옮기면, 연결된 임대 수입·임시 거주비·이주비 대출이자·분담금·세금 판정·자산 가치와 현금 부족 시점이 함께 바뀌고, 변화 이유가 화면에 나와야 한다. 어떤 일정이 준공에 따라 움직이는지는 계약별로 명시한다.

## 문서만으로 충분한가

문서를 개발 기준으로 삼되, **기존 기능 기준선 → 클릭 가능한 화면 시제품 → 계산 정답 사례 → 작은 기능 단위 구현**을 함께 사용한다. R0에서 현재 자산 관리의 보존 범위를 확인한 뒤 기존 계산·저장 오류를 복구한다. 이어 **부동산 없는 사용자의 현금·연금·생활비 전망**을 완결하고 일반 부동산·임대·재건축을 조건부로 확장한다. 전 과정에서 일상적인 시세 갱신·계좌/종목·이력·배당 관리를 회귀 검수한다.

## 검토 범위와 한계

- 코드와 기존 문서를 읽어 분석했다. 실제 개인 자산 데이터에는 접근하지 않았다.
- 설치 없이 진행하자는 합의에 따라 추가 설치를 하지 않았다. 기존 앱의 테스트·빌드·실기기 검증은 수행하지 않았다. 별도 전체 시제품은 설치돼 있던 Chrome으로 화면과 편집 동작을 확인했다.
- 아래 문서의 ‘코드 확인’은 정적 경로 확인이며, ‘수치 예’는 코드 식을 따라 계산한 합성 사례다. 런타임 재현 성공으로 해석하면 안 된다.
- 앞서 준비한 [진단 스크립트](verify-baseline.cjs)는 의존성 미설치로 실행되지 않았다. 향후 설치된 개발 환경에서 기준 커밋의 동작을 확인할 보조 자료다. 올바른 세법을 검증하는 테스트가 아니다.
- 법령·공식 안내는 설계의 주요 전제를 확인하는 데 사용했다. 완전한 2026년 세무 계산 규격이나 미래 세법을 확정한 문서는 아니다.
- 변경 산출물은 `docs/redesign/`에만 있다. 앱 기능·기존 데이터·원격 저장소는 변경하지 않았다.
