# 09. 실제 앱 적용·검증 기록

최신 후속 변경은 [12. 화면 간소화](12-simple-daily-workflow.md)를 우선합니다. 현재 테스트 158개 통과, 계획 첫 화면 입력칸 0개, 단계별 실제 클릭·저장·재열기와 실제 백업 23개 경로의 PC/모바일 확인을 추가했습니다.

최종 확인일: 2026-09-15. 기준 앱 커밋: `053f83ec698d74fa37ba2280b00ee8a4ba388a1c`.
초기 시제품이나 R1-A만의 보고가 아니라 현재 `frontend/src`에 반영한 개편의 기록이다.
원격 push/배포는 하지 않았다. 현재 작업 트리의 소스·문서를 ZIP으로 전달한다.

사용법과 화면 대응은 [적용 안내](APPLIED-REDESIGN.md), 합성 데이터로 촬영한 화면은
[실제 앱 화면 모음](actual-screens.html)을 참고한다. `full-app.html`은 초기 설계 시제품이다.

## 후속 수정: 이전 백업 가져오기 호환성 (2026-09-15)

사용자가 제공한 구버전 백업으로 실패를 직접 재현했다. 취득일 미입력을 `null`로 저장한
원본을 새 검증에서 거부한 호환성 결함이었다. 날짜 값을 임의 생성하지 않고 DB/백업의
`null`을 보존하며, 앱 조회 단계에서만 빈 입력으로 표현하도록 수정했다. 잘못된 날짜,
숫자/객체 타입, 필수 키 누락을 거부하는 안전 검증은 유지한다.

- 실제 파일의 자산 54행·평가 이력 7,016행을 포함해 모든 원본 테이블을 가져오기/내보내기
  전후 대조했다. v2 재내보내기 후 재복원도 원본 필드 값 그대로 보존했다.
- 별도 Chrome 프로필에서 실제 파일 입력 컨트롤로 업로드하고 복원 확인을 거쳐 성공했다.
  홈·전체 자산·주식·계획·설정을 다시 연 뒤에도 원본 테이블 일치를 확인했다.
- 실제 파일 검사는 외부 요청을 차단하고 화면 캡처·개인 데이터 결과 로그를 생성하지 않는다.
  테스트 종료 시 임시 브라우저 저장소/프로필을 삭제했다. 원본 파일과 평소 브라우저는 그대로다.
- null 취득일의 구 백업/새 분석/v2 왕복과 잘못된 날짜 원자적 거절 회귀를 추가했다.
  수정 후 **10개 파일, 147개 테스트 및 제품 빌드 통과**. 아래 145개 결과는 최초 개편 검증 기록이다.
- 재현 도구: `node tools/check-backup-compat.cjs <백업 경로>` (메모리 DB),
  `node tools/check-local-app.cjs --backup <백업 경로>` (실제 로컬 UI, 전용 임시 프로필).
  개인 파일은 소스·테스트 fixture·전달 ZIP에 포함하지 않는다.

후속 실제 화면 검증에서 확인한 8건은 사용자의 적용 요청 후 보완했다.
[10. 수정 전 검증](10-imported-data-ui-review.md), [11. 보완 적용·재검증](11-review-fixes-applied.md)을
함께 읽는다. 최신 회귀 검사는 11개 파일/154개 테스트이며 모든 업무 시나리오 인수 완료를 뜻하지 않는다.

브라우저 검사는 새 임시 Chrome 프로필과 합성 자산만 사용했다. 일반 DB가 빈 상태로
유지되고, 가상의 배우자·자산이 자동 생성되지 않으며, 재건축 미보유 시 전용 요약이
나오지 않는 것을 확인했다. 실제 시세 대신 모의 응답을 사용하고 외부 HTTPS는 차단했다.
검사 내 날짜는 합성 기준일로 고정해 자정이 지나도 결과를 재현하도록 했다.

검사에는 실제 계획 폼 편집·저장·재조회, 기존 수동 보유세 보존, 저장 사본과 월별 상세,
동일 사본의 지연 시나리오 비교, 잘못된 백업의 원자적 거절이 포함된다. 모든 버튼·키보드
동작·실기기 접근성·전체 자산 업무 시나리오의 수동 인수 검사를 대체하지는 않는다.

## 재현 방법과 증거

저장소 루트에서 실행한다. Docker와 별도 DB 서버는 필요 없다.

```powershell
powershell -NoProfile -File .\tools\wsl-dev.ps1 -Action test
powershell -NoProfile -File .\tools\wsl-dev.ps1 -Action build
powershell -NoProfile -File .\tools\wsl-dev.ps1 -Action dev
node tools/check-local-app.cjs
node tools/check-local-app.cjs --production
powershell -NoProfile -File .\tools\package-transfer.ps1 -SourceOnly
```

새 환경의 최초 설치는 [WSL 안내](../WSL-DEVELOPMENT.md)를 따른다. 브라우저 검사는
Windows의 기존 Node/Chrome을 사용하며 개발 검사는 5173 서버가 필요하다.
제품 빌드 검사는 자체 로컬 서버를 열어 빌드 파일을 확인한다.

- 테스트/빌드 증거: `logs/delivery-test.out.log`, `logs/delivery-build.out.log`.
- 브라우저 증거: `logs/local-app-check/result.json`, `production-result.json`.
- 실제 앱의 합성 화면 8장은 `docs/redesign/screenshots/actual/`에 포함한다.
- `logs/`와 임시 브라우저 프로필은 Git/소스 ZIP에 포함하지 않는다. 위 검사로 재생성한다.
- 소스 포장 도구는 압축 안의 **모든 파일 SHA256를 원본과 대조**하고 크기·전체 ZIP 해시를
  함께 출력한다. 전체 소스·문서판과 화면 이미지 제외 소형판을 만든다.

## 데이터 영향과 배포 전 경계

- 기존 개인 DB를 열거나 실사용 백업을 가져오지 않았다. IndexedDB v2는 계획·결과·초안·
  복구 테이블을 추가한다. 기존 자산을 자동 이전/삭제하거나 샘플로 채우지 않는다.
- 계획에서 기존 은퇴 입력을 가져올 때는 검토용 초안이다. 연도만 있는 날짜·복잡한 법인/
  보험 가정 등을 자동 확정하지 않는다. 원본과 비교해 확인해야 한다.
- 재건축 준공만으로 모든 세금이 시작하거나 그 이전 세금이 0원이 된다고 가정하지 않는다.
  확인한 예상 세액의 적용기간·납부월·근거를 입력한다. 한국 세법 전체, 건강보험, 공동소유,
  취득·양도 특례와 법인-개인 통합 세무를 자동 판정하는 엔진은 제공하지 않는다.
- 원본 이력 차트는 연결 보정 전 기록이다. 현재 합계와 새 월별 분석의 집계 규칙을 명시하며
  과거 실적 완전 복원·역사적 환율·확률적 은퇴 성공률은 제공하지 않는다.
- 실시간 공급자 접속, Google 인증, 실제 개인 백업 최초 복원, Android/iOS 설치와 기존 PWA
  업데이트는 배포 전 실제 환경에서 별도 확인해야 한다. 최초 복원 전 원본 백업을 보관한다.
- 소스 ZIP에는 `.git`, `node_modules`, `dist`, 로그, 환경/비밀 파일, 기존 개인 화면 캡처,
  브라우저 금융정보를 넣지 않는다. 소스 이동 후 의존성 최초 설치는 필요하다.
- GitHub push·원격 배포·보안 우회는 하지 않았다. 로컬 구현/검증 결과를 소스로 전달한다.
