# 대화에서 합의한 연금 계획 등록

## 적용 경계

- IndexedDB는 사용자 브라우저마다 별개다. 테스트 프로필 성공을 사용자 브라우저 저장 완료로 보고하지 않는다.
- `pension-plan-registration` JSON을 설정의 가져오기로 선택하면 전체 백업 복원이 아니라 **해당 연금 계획만** 트랜잭션으로 병합한다.
- 현재 자산 잔액, 주식·시세·거래 이력, 생활비·여행비·의료비, 다른 연금, 미확인 세금 값은 보존한다. 적용 직전 설정·연금 상세는 로컬 복구 영역에 보존한다.
- 개인별 ID와 금액이 있는 실제 등록 파일·백업은 저장소 밖에서 보관한다. 테스트 소스에는 합성 데이터만 사용한다.

## 월별 계산

- `pension_sim_plan.monthlyPlan`에 계좌 역할(회사 DC/개인IRP/보험), 월별 납입, 이전·목돈 입금월, 수령 시작·종료월, 총수익률, 매 수령기념월 증가율을 저장한다.
- 기존 `annualPension`의 연간 결과 형식을 유지하면서 지정 계좌만 월별 원장으로 대체한다. 다른 연금과 일반 주식은 기존 계산을 유지한다.
- 월초 잔액에 유효 월수익률을 적용한 뒤 월말 납입·내부 이전·지급한다. 총수익률에는 배당이 포함되며 공통 배당률을 다시 더하지 않는다.
- 기간형 IRP의 최초 지급액은 개시 잔액과 남은 월수, 총수익률, 연 증가율을 이용해 월별 현재가치로 산정한다. 등록돼 있던 고정 월액을 비례 확대하지 않는다.
- 회사 DC 이전은 자산 증가가 아니다. 이전 후 DC의 별도 연금 지급은 중단한다. 목돈은 원래 목돈·분배 항목을 참조해 한 번만 반영한다.
- 보험 지급형 연금은 금융기관 조회액 가정이다. 미래 보험료를 계좌 잔액 또는 수령액에 임의로 더하지 않는다.

## 불확실성·제한

- 개인IRP 과세제외 원금 미확인은 0원이 아니다. 과세 재원 확인 전 해당 인출 세금은 미확정으로 표시한다.
- 회사 DC 및 위로금의 이연퇴직소득세율은 자동으로 만들지 않는다. 위로금의 퇴직소득·IRP 입금 가능 여부도 확인 대상이다.
- 기존 비과세 설정과 대화의 연금저축 설명이 충돌하면 기존 설정을 보존하되 확인 전 해당 연금 세금을 확정하지 않는다.
- 월별 계획은 분석의 명시적 우선 조건이다. 연간 편집 항목을 바꿔도 월별 계획을 자동 재해석하지 않는다. 등록 요약에서 적용 조건과 미확인 항목을 확인한다.
- 미래 납입은 계획상 연금 유입이다. 실제 현재 자산 또는 거래 이력에 가산하지 않으며, 다른 현금계좌에서 자동 차감하거나 세액공제 환급을 확정하지 않는다.
- 연간 결과를 12로 나눈 월액은 연평균이다. 첫해 4월 개시는 9개월, 마지막 3월 종료는 3개월만 수령한다.

## 검증

`monthlyPension.test.ts`: 360회 수령, 첫해·종료연도 부분 지급, 매년 4월 증가, 자본 대사, 내부 이전, 총수익률, 미확인 세금, 부분 조회, 트랜잭션 보존, 중복 등록, 백업 왕복.

`tools/check-local-app.cjs --backup <원본> --register-pension --plan-file <계획 파일> --output-backup <새 백업>`: 격리 Chrome에서 실제 파일 선택으로 등록하고 PC/모바일 요약, 계산 원장, 실제 내보내기·가져오기를 점검한다. 외부 요청은 차단한다. 결과물은 새 백업이며 사용자의 현재 브라우저는 변경하지 않는다.
