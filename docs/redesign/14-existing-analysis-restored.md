# 기존 입력 중심의 분석 복귀

적용일: 2026-09-16. 12번의 신규 계획 중심 사용 순서를 대체한다. 현재 자산 관리와 기존 연도별 분석을 기본으로 사용하고, 별도 월별 계획은 고급 기능으로 보존한다.

후속 보완: [15. 시점·지급·잔액 연결](15-analysis-reconciliation.md). 아래 한계 중 주택 과세대상 전환일, 인별 보유세, 연금 지급액과 잔액 대사는 후속 구현을 우선한다. 실제 납세 사실관계를 자동 판정한다는 뜻은 아니다.

## 사용 순서

1. **홈 → 주식 계좌 확인·시세 갱신**: 기존 계좌별 종목·시세·배당·이력을 관리한다.
2. **분석 → 분석 요약**: 기존 자산·연금·배당·생활비와 저장된 연동 설정을 읽어 결과를 표시한다. 새 계획 작성이나 분석 실행 버튼은 필요 없다.
3. **월 수입 / 월 지출**을 누르면 구성 내역이 열린다. 세금·건강보험 상세도 펼쳐 확인한다. 연도를 바꾸면 해당 연도를 계산한다.
4. 수정이 필요할 때만 **생활비·목돈 입력** 또는 **연결된 입력 확인**에서 원래 입력 화면으로 이동한다. 저장하면 요약·현금흐름에 반영된다.

등록 정보가 없는 사람에게 예시 생활비·연금 금액을 실제 결과처럼 표시하지 않는다. 은퇴 연도·생년월(또는 기존 나이)·생활비 입력이 없으면 필요한 화면을 안내한다. 명시적으로 저장한 빈 생활비 목록은 0원으로 존중한다. 의료비 미입력은 별도 안내한다.

## 화면 대응

| 용도 | 현재 주소 / 동작 |
|---|---|
| 기본 메뉴 | 홈 · 자산 · 분석. 설정 접근은 유지 |
| 분석 요약 | `/analysis` |
| 연도별 현금흐름 | `/analysis?tab=cashflow` |
| 기존 생활비·목돈 입력 | `/analysis?tab=prep` |
| 기존 연금 / 법인 계산기 | `/analysis?tab=pension-sim` / `corp-sim`, 세부 계산에서 접근 |
| 별도 월별 계획 | `/plan`, 고급 기능으로 보존 |
| 보관한 월별 분석 | `/advanced-analysis`; 기존 `/analysis?run=…` 링크도 유지 |
| 과거 주소 | `/legacy-analysis`는 탭을 유지해 기본 분석으로 연결. `/prep`, `/retirement`, `/pension/sim`도 해당 기존 화면으로 연결 |

## 입력 연결 규칙

- `analysisInputs.ts`에서 기존 입력을 읽기 전용으로 정규화한다. 화면 열기만으로 설정·계획을 저장하거나 이전 데이터를 삭제하지 않는다.
- 은퇴 연도는 저장된 은퇴 입력이 우선이고, 없을 때 설정의 연도를 사용한다. 기존 수동 보유세 및 법인/연금 연동 선택은 임의로 바꾸지 않는다.
- 요약과 연도별 현금흐름은 같은 `useAnalysisEngine`을 사용한다. 기존 연금 편집 화면도 같은 연금 원천 해석을 사용한다.
- 자산에 연결된 연금 원금은 과거 시뮬레이션 사본 대신 현재 자산 평가액을 사용한다. 연결 주식 계좌 잔액도 다시 읽는다. 수동 원천·수익률·명의·세금 분류 설정은 보존한다.
- 처분 자산은 분석용 활성 자산과 연금 원천에서 제외한다. 주식 자산 변경 시 배당 요약 캐시도 갱신한다.
- 기본 연금 계산에서 등록 국민연금과 개인연금을 구분해 표시한다. 합계를 두 번 더하지 않는다.
- 연도별 계산 시작은 고정된 2029년이 아니라 올해다. 요약의 최초 선택은 은퇴 연도이며 계산 범위 안으로 제한된다.
- 현금흐름 설정 저장은 수정한 필드만 반영한다. 다른 화면에서 저장한 생활비를 오래된 사본으로 덮어쓰지 않는다.

## 검증

- 단위 테스트: 13개 파일, 170개 통과. 신규 6건은 입력 누락, 출처 우선순위, 현재 잔액 갱신, 수동 설정 보존, 처분 제외, 국민/개인연금 분리 등을 검증한다.
- TypeScript 검사 통과.
- 기존 브라우저 회귀 검사와 배포용 화면 기동 검사 통과. 주식 시세 성공·실패는 외부 API 대체 응답으로 확인했으며 실제 금융사 조회·Google 인증을 이번에 검증한 것은 아니다.
- 격리 브라우저의 가상 데이터로 1440px / 390px 화면, 기본 요약, 수입·세금 펼치기, 탭 이동, 생활비 수정 후 자동 재계산을 확인했다. 기본 분석은 새 월별 계획을 생성하지 않았다.
- 업로드된 실제 백업은 격리 프로필에서 읽기 전용으로 검증했다. 같은 두 화면 너비에서 기존 분석과 세부 계산기를 열고, 내보낸 원본 테이블이 모두 동일함을 확인했다. 원본 파일도 바꾸지 않았다. 실제 금융정보는 화면 촬영·결과 출력·저장소 포함·외부 시세 전송하지 않았다. 임시 프로필은 검증 후 제거했다.
- 재현 도구: `tools/check-local-app.cjs --analysis`. 실제 백업 검사는 `--backup <파일> --analysis`를 추가한다.

## 여전히 구분해야 할 한계

이번 단계는 **새 입력 절차를 줄이고 기존 결과의 연결을 보완**한 것이다. 전체 금융 모형을 새로 완성하거나 세법 정확성을 인증한 것이 아니다.

- 세금·건강보험은 기존 간이 모형이다. 실제 납부액, 최신 법령, 개인별 모든 공제·자격을 검증하지 않았다.
- 재건축은 기존 `futureYear` / `futureValue`에 따른 연도별 가치 전환을 유지한다. 정확한 준공일·과세기준일·취득세·임대 개시를 자동 판정하는 기능까지 구현한 것은 아니다. 해당 자산이 있을 때 요약에 주의를 표시한다.
- 연금/법인 연동 여부와 수동 가정을 유지하므로 같은 자산이라도 저장된 연동 방식에 따라 결과가 달라질 수 있다. 입력 출처와 모드를 확인할 수 있게 했다.
- 기존 계좌 잔액 전망은 별도의 단순 성장·인출 가정을 사용하는 참고 계산이다. 모든 실제 계좌 잔액과 현금흐름이 월별로 대사되는 통합 원장이라고 해석하면 안 된다.
- 기존 근로소득 등 미등록 현금흐름은 자동 추정하지 않는다. 누적 현금흐름은 입력된 항목의 누적이며 현재 총자산이나 은퇴 성공 확률이 아니다.
- 고급 월별 계획/보관 결과는 별도 가정과 스냅샷이다. 기본 연도별 분석과 합산하거나 항상 같은 결과라고 표시하지 않는다.

추가 설치 및 Docker는 필요하지 않았다. 작업은 로컬 소스에 적용했으며 이번 단계에서 Git 커밋·푸시는 하지 않았다.
