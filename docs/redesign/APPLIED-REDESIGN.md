# 현재 자산 관리 + 은퇴설계: 적용된 개편 안내

이 문서는 `frontend/src`에 반영한 실제 앱의 동작·사용법·지원 경계를 설명한다.
`full-app.html`은 초기 설계 시제품이며 실제 제품이 아니다. 현재 구현의 기준은 이 문서와
[검증 기록](09-implementation-progress.md), 코드·테스트다.

**추가 보완:** 실제 이전 백업에서 확인한 계좌 그룹화·연결 연금 출금 원천·기존 전망 표시 등
8건을 수정했다. 최신 UI/연결 계약은 [11. 보완 적용](11-review-fixes-applied.md)을 함께 따른다.
이 문서의 ‘보존/구현’은 모든 업무 시나리오의 인수 통과를 뜻하지 않는다.

## 1. 무엇이 바뀌었나

현재 자산 관리는 그대로 독립적으로 사용한다. 주가 갱신, 계좌/종목 상세, 수량·취득가,
평가 이력, 실제 배당, 부동산·연금·예적금, Google Drive 연결 경로를 유지했다.
은퇴 입력을 채워야 주식 화면을 사용할 수 있게 만들지 않았다.

미래 분석은 새 **월별 원장**을 사용한다. 현재 입력을 읽어 계산 당시 사본을 만들고,
그 사본과 시나리오·계산 버전을 결과에 함께 저장한다. 새 가격이나 계획 수정으로
기존 분석이 조용히 달라지지 않는다. 수급권, 계좌 잔액, 부채, 생활현금을 구분한다.

|---|---|---|
| 홈 `/` | 현재 자산 우선 홈 | 현재 합계, 자산 관리 바로가기, 별도의 저장 계획/변경 알림 |
| 기존 대시보드 | `/history` | 원본 자산 이력 대시보드 보존 |

데스크톱 메뉴에서 접근한다. 자산 유형과 분석의 결과/연도/월 선택은 주소에 남는다.

## 3. 입력과 계산의 연결

| 원천 | 새 분석의 사용 방식 |
|---|---|
| 현재 자산 평가액·수량·상세 | 새 계산 때 읽어 스냅샷 보관. 실제 기록을 미래 시나리오로 덮지 않음 |
| 연금 수급권 | 투자 원금에서 제외. 지급 일정의 외부 수령액으로만 반영 |
| IRP·연금저축 등 계좌 | 계좌별 잔액을 유지하고 실제 인출은 가용 잔액까지만 지급 |
| 자산에 등록한 월 연금액 | 계획의 ‘자산에 등록한 연금 지급액 연결’로 원본 참조 생성. 원본 금액 변경은 새 분석부터 반영 |
| 같은 잔액을 나타내는 중복 기록 | 자산 연결에서 원본 자산을 지정하거나 합산 제외. 실제 기록은 삭제하지 않음 |
| 부동산 대출·받은 보증금 | 현재 원본 잔액과 연결. 0원 상환도 반영. 자산 처분만으로 부채가 자동 소멸하지 않음 |
| 지급한 보증금/예치금 | 자산. 반환/회수는 현금과 자산 사이 이동이며 소득이 아님 |
| 급여·연금·임대료·생활비 | 적용기간·주기·지급일·귀속인·금액 증가율이 있는 입출금 |
| 매각·대출·분담금·목돈 | 지정한 날짜의 사건. 미래 목돈으로 그 이전 지출을 충당하지 않음 |
| 세금·보험료 | 적용 범위/기간/근거를 가진 사용자 예상 납부액. 법령 자동 판정이 아님 |

계획의 ‘미입력’, ‘없음/0 확인’, ‘입력함’은 구분된다. 없음 확인과 양수 입력이 충돌하면
오류로 표시한다. 미확정 항목이 있으면 참고 계산은 가능하나 은퇴가 안전하다는 판정을
하지 않는다. ‘입력 확인 완료’ 역시 수익 보장·세법 검증·은퇴 성공 확률을 뜻하지 않는다.

### 현재 합계와 이력 차트의 구분

홈·자산 전체·주식 현재 합계는 같은 중복 제외 규칙을 사용한다. 주식 종목 타일의 원본
평가액·수량은 계속 볼 수 있다. 기존 자산 이력 차트는 **원본 이력 합산, 연결 보정 전**이다.
과거 계좌 구조를 확인 없이 재작성하지 않았다. 새 은퇴 분석의 연간 합계·추세·월별 내역은
모두 같은 월별 원장에서 나온다.

## 4. 재건축을 입력하는 방법

재건축을 보유하지 않으면 홈의 재건축 전용 요약이 나타나지 않는다. 일반 자가 보유만으로
재건축·임대 수입을 자동 생성하지 않는다.

1. **자산**에서 현재 보유한 부동산/권리의 현재 평가액과 실제 부채를 관리한다.
2. **계획 → 자산 연결**에서 ‘공사·재건축 중’ 또는 ‘권리’를 확인한다.
3. **일정·목돈**에서 준공, 사용승인, 입주, 예상 평가액 변경을 필요한 만큼 따로 등록한다.
4. 임대 시작이 사용승인 뒤라면 임대 수입의 시작을 ‘사용승인 + N개월’로 연결한다.
5. 분담금이 계약상 고정일이면 고정 날짜로 둔다. 준공과 함께 옮기면 안 되는 납부일을
   일괄 이동하지 않는다.
6. 세금은 적용기간과 납부월을 나눠 입력한다. 예를 들어 공사 중 적용기간의 끝을
   ‘사용승인 − 1일’, 이후 적용기간의 시작을 ‘사용승인’에 연결할 수 있다.
   연간 납부월은 별도로 지정할 수 있다. 빈 납부월은 시작월에 연동한다.
7. 공사 중 세액이 미정이면 미확정 상태를 유지한다. 정말 0원이라고 확인한 구간은
   0원·기간·근거를 명시한다. 준공 후 항목 하나만 입력해서 그 이전을 자동 0원으로
   확정하지 않는다.
8. **대안**에서 준공을 12개월 늦춰 저장하고 분석한다. 연결한 사용승인·임대·세금 기간은
   이동하고, 고정 분담금 날짜는 유지되는지 날짜 목록과 원장을 비교한다.

6월 1일 부동산 상태는 납부와 분리한 검토용 목록이다. 시가·공시가격·입력 과세표준을
구분하지만 그것만으로 주택 수·권리/토지 과세 여부·취득세·양도세를 확정하지 않는다.

## 5. 월별 계산 계약

- 기준일은 **그 날 마감 잔액**이다. 계산은 다음 날 시작한다. 현재 저장 평가액을 출발점으로
  사용하며 과거 기준일의 실제 자산을 자동 복원하는 백테스트 기능은 아니다.
- 가격을 새로 갱신했다면 계획 기준일도 확인한다. 기준일 뒤 관측 이력이 섞이면 분석을
  막고 확인을 요구한다. 과거 결과는 해당 결과의 저장 사본으로 열람한다.
- 현금이 부족하면 명시적으로 허용한 투자/연금 계좌를 목록 순서로 인출한다.
  원천징수가 있으면 순액을 기준으로 충당한다. 인출과 관련 세금은 목표액이 아니라 실제
  인출액을 기준으로 계산한다. 미지원 매각차익 과세는 별도 예상 세금으로 입력한다.
- 주식 가격 상승과 배당을 분리한다. 일별 기초 잔액에 월복리 환산 가격 상승을 적용하고,
  원 단위로 반올림해 월별로 합산한다. 당일 유입은 다음 날부터 수익 가정에 노출된다.
  배당은 일별 잔액에 대해 발생을 가정해 월말 지급한다. 실제 배당락/지급일 모델이 아니다.
- 대출은 일별 잔액의 단리 이자를 월말에 납부한다. 만기 원금은 해당 날짜, 정기 원금은
  월말에 지급한다. 원리금 균등은 입력한 약정 월 납부액을 사용한다. 금융기관 상환표·연체료·
  중도상환수수료를 자동 재현하지 않는다.
- 미충당 비용은 별도 계획상 부담으로 표시하며, 이후 당기 요청 처리 후 남은 현금으로
  발생 순서대로 충당한다. 미상환 원금은 원래 부채에 남으므로 다시 부채로 이중 차감하지 않는다.
- ‘요청 미충족’에는 지출 부족뿐 아니라 인출·적립 목표 미달도 포함된다. 실제 채무 발생의
  법적 판정이 아니다. 원장에서 어떤 요청이 부족했는지 구분한다.
- 동일한 날에도 자산 상태/평가·자산 거래, 정기 입출금, 일회성 납부 등 명시된 처리 순서를
  사용한다. 시간 단위 결제 시뮬레이션은 아니며 실제 계약의 당일 자금 조달 순서는 따로 확인한다.
- 원천세 정산은 지정한 귀속연도에 납부한 지정 원천의 금액을 한 번 공제한다.
  이를 종합소득세 신고 엔진이나 절세 최적화로 해석하면 안 된다.
- 현재 구매력 보기는 표시 환산이다. 연간 표와 CSV는 명목 원화이며 CSV 숫자는 합산 가능하다.

## 6. 저장·복원·샘플 보호

IndexedDB v2는 `plannerPlans`, `plannerRuns`, `plannerDrafts`, `plannerRecovery`를 **추가**한다.
실제 자산·이력·배당 테이블을 자동 변환하거나 삭제하지 않는다.

- 계획은 revision 비교 후 원자적으로 저장한다. 다른 탭의 변경을 덮어쓰지 않고 초안과
  충돌 안내를 남긴다. 초안은 탭 단위로 별도 저장하며 재접속 시 복원한다.
- 동일 조건의 분석은 같은 식별자를 재사용하고 기존 저장 사본은 덮어쓰지 않는다.
  입력/자산/계산 버전이 달라지면 현재 결과와의 차이를 알린다.
- 기존 은퇴 입력은 미리보기로 검토용 초안에 복사한다. 연도만 있는 날짜의 월을 임의로
  확정하지 않는다. 복잡한 여행 구간·기존 법인/보험 가정은 원본과 대조해 새 입력으로 확인한다.
- 복원은 파일 구조·필수 테이블·수치·날짜·참조·중복 ID·분석 연결/합계 검증 후 확인을 받는다.
  미리보기 뒤 입력이 바뀌면 다시 검토해야 한다. 전체 교체는 한 트랜잭션으로 처리한다.
- 직전 복원 사본을 보관해 되돌릴 수 있다. 이 사본은 다음 복원 시 교체되며 같은 브라우저에만
  있다. 브라우저 저장소 삭제나 기기 분실에 대비한 외부 백업을 대신하지 않는다.
- 복원/이력 저장 때 기록 없는 날짜를 실제 관측처럼 추가하지 않는다. 연속 보기는 표시만 한다.
  과거 수량 수정은 그 날짜에만 적용하고 이후 실제 거래로 전파하지 않는다.
- 국내 과거 시세 보정은 기존 관측일만, 최근 3개월/오늘 제외로 미리 본다. 외화는 과거 환율을
  확보하지 못했으므로 이 보정에서 제외한다. 원본 수량/현재 평가액을 보존하고 마지막 보정을
  되돌릴 수 있다. 그 뒤 해당 기록이 다시 바뀌었다면 자동 되돌리기를 중단한다.
- 샘플은 `?demo=1`로 열린 별도 저장소 `asset_manager_m_demo`에만 자동 생성한다.
  일반 저장소는 빈 상태로 시작한다. 샘플에서 돌아가기도 제공한다.
- PWA 업데이트는 저장 확인 후 사용자 동의로 적용한다. 실제 설치 앱 간 업데이트는 별도 검수한다.

JSON 백업에는 개인 금융정보가 평문으로 들어 있다. 승인된 개인 저장 위치·전달 경로를 사용한다.
소스 ZIP에는 IndexedDB 개인 자산, `.git`, 환경 파일, 설치 의존성, 로그, 기존 개인 화면 캡처를 넣지 않는다.

## 7. 실행과 개발팀 전달

Docker·Python 백엔드는 필요하지 않다. 이 환경에서는 WSL의 격리된 Node 22와 기존 잠금파일
의존성으로 실행/검증한다. 추가 라이브러리는 설치하지 않았다.

```powershell
# 저장소 루트에서, PowerShell → WSL 실행
powershell -NoProfile -File .\tools\wsl-dev.ps1 -Action dev
# 확인: http://127.0.0.1:5173

powershell -NoProfile -File .\tools\wsl-dev.ps1 -Action test
powershell -NoProfile -File .\tools\wsl-dev.ps1 -Action build

# Windows의 기존 Node/Chrome으로, 별도 프로필의 가상 데이터만 사용
node tools/check-local-app.cjs
node tools/check-local-app.cjs --production

# 소스만 포장하고 모든 ZIP 항목의 SHA256를 원본과 대조
powershell -NoProfile -File .\tools\package-transfer.ps1 -SourceOnly
```

새 환경에서는 [WSL 실행 안내](../WSL-DEVELOPMENT.md)를 따른다. `node_modules`는 ZIP에 없으므로
최초 1회 잠금파일 기반 설치가 필요하다. 로컬 주가 프록시는 Vite, 배포 시에는 기존 Vercel API
설정이 필요하다. 정적 파일만 올린 서버에서 `/api/price`가 자동 생성되는 것은 아니다.

| 코드 | 역할 |
|---|---|
| `frontend/src/planner/model.ts` | 입력 계약, 원천 연결, snapshot, 적용 여부 |
| `engine.ts` | 날짜 해석·월별 원장·잔액/세금/부채·연간 집계 |
| `storage.ts`, `context.tsx` | revision, 초안, 분석 보관, 현재 데이터 읽기 |
| `backup.ts` | 복원 경계 검증 |
| `pages.tsx`, `planner.css` | 실제 홈·계획·분석·자산 전체/직접 상세 |
| `frontend/src/lib/db.ts` | 기존 자산 DB, 원자적 복원, 안전한 시세 관측/보정 |
| `engine.test.ts`, `storage.test.ts`, 기존 lib 테스트 | 계산·저장·기능 보존 회귀 |

## 8. 명시적 지원 경계와 배포 전 확인

이 구현은 **연결된 현재 자산과 사용자 가정으로 작동하는 결정적 은퇴 계획 도구**다.
처음 설계 문서의 모든 장기 확장 항목을 구현/인수 통과했다는 뜻은 아니다.

- 한국 세법 전체 자동 계산, 복잡한 공동소유/다주택/조합원 권리 판정, 최신 건강보험 산정,
  취득·양도 특례, 연금 세원별 최적 인출, 법인-개인 통합 세무는 자동 확정하지 않는다.
  확인한 기간별 예상액을 새 원장에 입력하고 기존 참고 계산기를 합산하지 않는다.
- 기존 구 계산기의 모든 내부 공식을 새 엔진으로 바꾼 것은 아니다. 접근·입력 보존을 위해
  분리한 참고 도구다. 주요 은퇴 판단은 새 월별 분석을 사용한다.
- 과거 실적 완전 재구성, 역사적 환율/거래별 원가 원장, 과거 계좌 구조 자동 대사,
  확률 시뮬레이션/성공 확률은 제공하지 않는다.
- 실사용자의 실제 백업·Google 계정·실거래 시세, Android/iOS 설치/업데이트, 원격 배포는
  이번 합성 데이터 로컬 검증과 별개다. 실제 데이터 최초 복원은 원본 백업을 따로 보관하고 확인한다.
- 회사 보안 정책이나 GitHub 권한을 우회하지 않는다. 원격 push/배포는 하지 않았으며
  전달은 검증한 소스 ZIP 기준이다.

최종 검사 결과와 실제 화면 이미지는 [09. 적용/검증 기록](09-implementation-progress.md)과
[실제 앱 화면](actual-screens.html)에서 확인한다.
