# 07. 개정안 — 현재 자산 관리와 미래 은퇴설계

작성일: 2026-09-14 · 개정 2  
사용자 확인: 이 앱은 은퇴계획뿐 아니라 평소 주식 시세를 갱신하고 계좌·종목 상세를 확인하는 자산 관리 도구다.

## 1. 방향 수정과 문서 우선순위

제품을 **“현재 자산을 꾸준히 관리하고, 그 기록을 바탕으로 미래를 설계하는 도구”**로 정의한다. 현재 자산 관리는 은퇴설계의 사전 입력 화면이 아니라 독립된 핵심 기능이다.

이전 개편안은 자산 CRUD·이력 보존을 명시했지만, 홈과 자산 상세를 은퇴 중심으로 단순화했다. 주식 시세·계좌별 종목·평가 정보·배당 실적에 대한 구체적인 유지 기준이 부족했다. 이 상태에서 시제품만 따라 구현하면 기존 사용성을 잃을 위험이 있다.

이 문서는 **제품 목적·홈 우선순위·현재 자산 기능 보존·현황과 전망의 경계**에서 이전 문서보다 우선한다. 나머지 도메인·세무·사건·저장 계약은 [05](05-implementation-spec.md)를 유지한다. 기존 기능 보존은 기존의 계산 오류나 위험한 덮어쓰기까지 유지한다는 뜻이 아니다.

개발 전달 시작점은 [개발 요청서](DEVELOPMENT-REQUEST.md)이며 `docs/redesign/` 전체를 함께 전달한다. 앱 소스·실제 자산·원격 저장소는 이번 개정에서 변경하지 않는다.

## 2. 두 가지 사용 목적과 연결

| 구분 | 현재 자산 관리 | 미래 계획·분석 |
|---|---|---|
| 사용 질문 | 지금 무엇을 얼마나 보유하고 있고 어떻게 변했나? | 앞으로 생활비를 충당할 수 있고 무엇을 바꾸면 되나? |
| 기본 데이터 | 보유 수량·원가 자료·시세·환율·잔액·평가 이력·확인된 배당 수령 | 기준일의 자산 스냅샷 + 소득·생활비·수익률·미래 사건·규칙 |
| 주요 동작 | 시세 갱신, 계좌→종목 조회, 기록·배당 입력, 현재 가치 수정 | 기간 설정, 사건 편집, 월별 계산, 원천 추적, 대안 비교 |
| 완료 조건 | 은퇴일·생활비가 없어도 등록·조회·갱신·백업 가능 | 부족한 입력은 부분 결과/확인 필요로 표현 |
| 변경 범위 | 새 실제 기록과 현재 상태를 갱신 | 미래 가정·시나리오만 변경. 실제 기록은 불변 |

단방향 연결은 `현재 기록 → 선택 기준일의 스냅샷 → 미래 시나리오 → 분석 결과`다. 미래 추정값을 현재 시세·과거 수량·배당 수령 실적으로 역저장하지 않는다. 실제 기록의 수정은 자산 관리에서 명시적으로 수행하고 변경 이력을 남긴다.

## 3. 메뉴와 홈 개편

`홈 / 자산 / 계획 / 분석`의 네 메뉴를 유지한다. 별도 앱이나 중복 데이터 저장소로 나누지 않는다.

- 홈: 현재 총자산·부채·순자산, 자산 구성, 기준일/시세 상태, 자주 쓰는 주식 관리 진입을 먼저 제공한다. 그 아래에 준비된 경우 은퇴 전망과 예정 사건을 배치한다.
- 자산: 통합 요약 아래 각 유형의 전문 화면을 유지한다. **주식 필터가 단순 자산 카드 목록으로 끝나지 않도록** 주식 관리로 연결한다.
- 계획: 미래 소득·지출·은퇴·사건·가정을 관리한다. 계획 작성은 선택적으로 시작하며 자산 관리 접근을 막지 않는다.
- 분석: 선택 기준일의 미래 전망·원천·시나리오를 제공한다. 현재 보유 상세를 찾기 위해 분석에 들어갈 필요가 없어야 한다.
- 설정: 백업·복원, 기존 시세 안내와 과거 시세 보정 경로를 보존한다. 기존 환율 데이터·외화 표시는 보존하고, 환율 출처·기준일·수동 수정 UI는 보완 기능으로 추가한다. 외부 시세 출처와 전송 범위를 안내한다.

은퇴계획 미입력 상태에서는 현재 자산 카드는 정상 표시하고 전망 영역에만 ‘계획을 입력하면 미래를 볼 수 있어요’를 제공한다. 앱 전체를 미완료로 가리지 않는다. 최초 진입에서 ‘자산부터 관리’와 ‘은퇴계획 시작’을 제공하며 강제 사용자 유형 선택이나 중복 계정은 필요 없다.

현재 변동액은 비교 기준일을 표시한다. 입출금·매매·환율 영향이 분리되지 않은 자산 증감을 투자수익이라고 부르지 않는다. 거래·원가 자료가 부족하면 실현손익·정밀 수익률은 확인 필요로 남긴다.

아래 ‘기존 근거’는 로컬 소스의 정적 확인이다. 실제 외부 시세 서비스 성공이나 모든 현재 계산의 정확성을 보증하지 않는다. 구현 시작 시 현재 브랜치에서 재확인한다.

AM-10에는 `Settings.tsx`의 **기존 선택형 Google Drive 로그인·폴더 선택·백업 저장·목록 새로고침·복원·로그아웃**도 포함한다. 로컬 JSON 백업과 함께 유지한다. 외부 계좌 자동 연동을 새로 도입하는 것과 기존 사용자 선택형 Drive 기능 보존은 다르다. 이번 검토에서 실제 Google 로그인·개인 자료 업로드를 실행하는 것은 아니다.

계좌·자산 명의를 위한 `Household/Person` 관리는 은퇴계획과 독립시킨다. 은퇴일·생활비 없이 가구원/명의를 설정할 수 있어야 하며, 계획 설정의 배우자 토글을 켜야만 공동/배우자 자산을 등록할 수 있는 구조는 피한다. 계획은 같은 사람 ID를 참조한다.

AM-10의 유형별 필드 이전·조회·편집 대응도 별도로 검수한다:

| 기존 대상 | 보존하고 새 도메인에 대응할 내용 |
|---|---|
| 주식·예적금의 연금형 설정 (`AssetForm.tsx`) | 연금형 여부·개시 연도·월 수령 목표를 해당 계좌 인출 계획으로 이전. 자산을 공적 지급권이나 중복 원금으로 전환하지 않음 |
| 연금 (`AssetForm.tsx`, `PensionPage.tsx`) | 종류·시작/종료 연도·월 목표·증가율·과세 구분·연결 주식계좌 보존. 차트 제외 설정의 의도를 확인하고 안정된 계좌 연결/중복 제거로 대체 |
| 부동산 (`RealEstatePage.tsx`, 자산 폼) | 현재 가치·주소/종류·소유/명의·부채/보증금·이력·기존 미래가치 원자료 보존. 미래연도를 준공으로 단정하지 않음 |
| 실물·기타 및 공통 자산 | 이름·취득일/원가·제공된 수량/단가/평가액·매각 상태·이력·메모 등의 실제 필드를 R0에서 추출해 이전 대응표 작성 |

과거 수량 정정은 ‘선택 날짜만’ 또는 ‘명시한 기간’을 고르고 변경 미리보기를 제공한다. 이후의 실제 수량 관측은 자동 덮어쓰지 않으며 필요 시 별도 확인한다. 되돌리기와 원본 보존을 제공하고, 표시용 직전 값 연장을 확정 관측으로 저장하지 않는다.

손익 계산은 별도 검증한다. 특히 현재 환율로 환산한 평단 원금과 취득 당시 원화 원가는 다를 수 있다. 현재 데이터만으로 취득 환율·수수료·매매 내역을 복원할 수 없다면 ‘현재 환율 환산 비교’처럼 계산 범위를 표시하고, 이를 전체 투자성과로 단정하지 않는다.

## 5. 주식 화면의 상세 설계

### 주식 관리 첫 화면

상단: 평가액, 제공 가능한 원금/손익과 산정 기준, 예상 배당, 마지막 시세/환율 기준. 주요 동작은 ‘시세 업데이트’, ‘종목/계좌 추가’다. 전체 갱신인지 선택 계좌 갱신인지 버튼에 범위를 명시한다.

본문: 계좌별 평가액·종목 수·비중 → 선택 계좌의 종목 목록. 종목 행은 수량·현재가·평가액·손익·시세 상태를 표시하고, 모바일에서는 필수 수치 위주로 접어 상세로 연결한다. 계좌 통합 모드에는 존재하지 않는 종목·수량을 생성하지 않는다.

### 종목 상세

탭은 `보유 현황 / 평가 이력 / 배당`으로 구성한다. 원천 수정과 미래 계획 반영 경로는 별도 동작으로 구분한다.

- 보유 현황: 실제 보유·가격·원가·환율 자료와 계산 근거, 수정, 매각 상태.
- 평가 이력: 날짜별 가격·수량·평가액·출처, 차트와 표. 당시 수량이 없으면 현재 수량으로 과거 보유를 확정하지 않는다.
- 배당: ‘실제 수령’과 ‘앞으로의 예상’을 구분한다. 예상 배당을 실제 입금에 자동 추가하지 않는다.
- 분석 연결: 어느 기준일·계좌·가정으로 새 전망에 반영되는지 표시한다. 과거 분석은 보존한다.

거래원장 신설, 증권사 자동 동기화, 실시간 틱 시세, 정밀 실현손익·TWR/IRR은 기존 보존 기능과 구분한 후속 확장이다. 기존 평가 이력을 매매 거래로 간주해 자동 전환하지 않는다.

## 6. 시세 갱신과 현황·전망 데이터 계약

1. 가격 관측에는 종목/시장/통화·출처·가격 기준시각·조회시각·상태를 저장한다. 환율은 별도 기준시각을 가진다. ‘조회 완료’를 ‘실시간 시세’로 표시하지 않는다.
2. 갱신 실패·오프라인이면 마지막 유효 가격을 보존하고 오래됨·실패를 표시한다. 0원으로 덮어쓰거나 일부 성공을 전체 성공으로 안내하지 않는다.
3. 같은 가격 재조회는 중복 배당·현금·수량 변경을 발생시키지 않는다. 같은 관측 식별자의 처리 정책을 정해 이력을 무한 증식시키지 않는다.
4. 관측 가격 갱신은 보유 수량·취득 원가·실제 배당을 변경하지 않는다. 시장가격과 장부 수정은 별도 명령이다.
5. 저장된 갱신 묶음의 revision으로 현재 종목·계좌·총자산 합계를 맞춘다. 계좌 안 종목과 계좌 통합 평가액을 동시에 합산하지 않는다.
6. IRP 등 연금과 연결된 투자 계좌는 경제적 잔액을 한 번만 집계한다. 주식 화면과 연금 화면은 같은 계좌를 다른 관점으로 보여주는 것이다.
7. 미래 분석은 명시된 기준일의 스냅샷을 사용한다. ‘최신 현황으로 계산’은 새 run으로 갱신하고, 저장된 과거 기준일 계획은 자동 변경하지 않는다. 새 시세가 있으면 재계산 필요 여부를 표시한다.
8. 시장 하락·배당 감소 대안은 override로만 적용한다. 현재 기록이나 다른 시나리오에 역전파하지 않는다.
9. 실제 배당 기록과 이미 입금된 계좌 잔액을 함께 가져올 때 동일 유입을 두 번 더하지 않는다. 평가만 갱신해도 생활 현금이 증가해서는 안 된다.
10. 과거 가격 정정은 관련 평가의 재작성 범위와 비교 결과를 안내한다. 기존 완료 분석 run과 당시 사용한 입력은 보존한다.

### 교차 점검으로 확정한 세부 계약

- **현황과 전망의 버전:** 현재 영역은 `assetRevision`, 전망 영역은 선택 `snapshotId/runId`를 사용한다. 동일 영역 안의 요약/상세 합계를 맞춘다는 뜻이지 과거 전망을 현재 revision으로 강제 갱신한다는 뜻이 아니다. 홈은 두 영역의 기준일과 새 현황 반영 여부를 표시한다.
- **계좌 평가 기준:** `valuationMode = accountTotal | holdingsDerived`와 상세 포함 범위를 저장한다. 종목 기반이면 계좌 현금·미분류 잔액을 포함해 대사하고, 부분 종목 등록만으로 계좌 총액을 대체하지 않는다. 통합 총액과 상세 합계 차이를 보여주며 모드 전환/기존 계좌 병합은 미리보기 후 확인한다. 계좌 100만 원 = 종목 80만 원 + 현금 20만 원이면 주식·연금 양쪽에서 보더라도 총액과 미래 기초자산은 100만 원이다. 불명확한 중복 후보를 자동 삭제하지 않는다.
- **과거 기준일:** `effectiveAt`(경제적 발생/관측 시점)과 `recordedAt`(등록/정정 시점)을 구분한다. 스냅샷은 기준일과 포함 경계를 명시한다. 기준일까지 잔액에 반영된 유입은 미래 원장에 재계상하지 않는다. 당시 보유량을 모르면 현재 수량으로 소급 확정하지 않는다. 월중 전망 시작 시 월 전체 급여/지출을 재반영하지 않도록 지급일과 기간 귀속 정책을 정한다. 정정 후 재작성은 새 스냅샷으로 만들고 이전 run을 보존한다.
- **시세 응답 순서:** 가격 저장과 수량/원가 수정은 별도 명령이다. 조회 중 수량 수정·매각·삭제가 발생하면 최신 보유 revision을 확인하고 오래된 요청의 수량을 되쓰지 않는다. 가격 기준시각과 요청 버전을 검증해 늦게 온 구시세가 최신 가격을 덮어쓰지 않게 한다. 수동 가격과의 충돌도 표시한다.
- **배당 기록의 기본 동작:** 현재 범위에서 수령 실적 추가/삭제는 기록만 변경하며 계좌 현금을 자동 입출금하지 않는다. 향후 현금 연결을 추가한다면 사용자 확인·연결 거래 ID·중복 방지·취소 계약을 별도로 구현한다. 이미 잔액에 포함된 배당의 실적 등록으로 총자산이 다시 늘어나면 안 된다.
- **원통화 정밀도:** KRW 보고금액과 원통화 금액·소수 단가·부분주·환율을 따로 보존한다. 저장/이전/복원에서 원자료 정밀도를 잃지 않으며 손익 계산의 환율/원가 범위를 표시한다.

현재 관측·실적, 미래 가정, 계산 결과는 저장과 화면에서 구분한다. 자산 조회와 계획 검증의 준비 상태도 분리한다. `planNeedsInput`이 `assetsReady`를 차단하지 않으며, 분석 로딩 실패가 현재 자산 목록을 빈 배열로 바꾸면 안 된다.

외부 시세 연결은 기존 경로를 보존하되 요청에 필요한 종목 코드·시장 등만 전송한다. 자산 금액·수량·명의를 새로운 외부 서비스에 전송하지 않는다. 공급자 교체나 데이터 라이선스·지원 범위 변경은 별도 확인 사항이다.

## 9. 수정 시제품과 검수 범위

[홈](full-app.html#/home)은 현재 자산을 먼저 보여준다. [주식 관리](full-app.html#/stocks)는 계좌→보유 종목→상세의 별도 전문 경로다. ‘자산 관리만’ 예시에서 은퇴 입력 없이 사용할 수 있는 흐름을 확인한다.

시세 갱신 버튼은 **고정된 가상 가격 적용**이며 실제 시장에 접속하지 않는다. 계좌 통합 값과 연결된 종목 샘플은 중복 집계하지 않는다. 이력·배당 탭의 데이터도 명시된 합성 예시다. 실제 배당 CRUD·과거 가격 보정·완전한 투자성과·영구 저장까지 이 시제품에서 구현한 것은 아니다. 해당 요구는 AM/C 목록으로 제품 구현을 검수한다.

시제품 테스트 통과와 실제 앱 기능 보존 검수는 다르다. 기존 앱 테스트·외부 시세 연동·실기기·개인 데이터 이전은 별도 검증이 필요하다.
