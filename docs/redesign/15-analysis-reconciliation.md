# 기존 분석의 시점·지급·잔액 연결 보완

2026-09-16. 14번 후속 적용 기록. 새 입력 체계를 추가하지 않고 기존 자산 편집과 분석을 연결한다. 이 문서의 변경 범위가 이전 문서보다 우선한다.

| 운용 가정 미입력인데 상승률 5%·배당률 4% 적용 | 미저장 기본값은 0%. 기존에 저장한 가정은 유지하고, 사용한 운용률을 분석에 표시 |

## 사용자가 확인하는 곳

기본 사용 순서는 **홈에서 주식 관리 → 분석에서 자동 결과 확인** 그대로다. 별도 월별 계획을 다시 작성할 필요가 없다.

재건축 자산에만 필요한 정보는 **자산 → 해당 부동산 → 속성 수정 → 상세 옵션 → 재건축 세금 시점 확인**에서 입력한다. 추가 필드는 접혀 있다.

- **주택 과세대상 전환일**: 실제 확인값 또는 사용자가 정한 계획 가정. 앱이 준공·실사용·사용승인에 관한 법적 사실을 자동 판정한 날짜가 아니다.
- **전환 전 연 보유세**: 토지 등까지 포함해 확인한 연 금액. 빈칸은 미확정이고, 확인한 금액이 0원이면 0을 입력한다.
- 기존 **입주 예정 연도 / 입주 후 예상 가치**는 그대로 재사용한다. 날짜가 없으면 연도 기준 가정을 사용했다는 안내가 나온다. 멸실 전 주택·상가·토지에 이 주택 모형을 그대로 적용하면 안 되므로 사실관계에 맞는 수동 보유세를 확인한다.
- 기존 수동 보유세를 선택한 경우 날짜 변경으로 수동 금액을 자동 덮어쓰지 않는다. 날짜와 연동하려면 연도별 현금흐름에서 보유세 자동을 선택한다.

분석에서 확인할 내용만 펼치면 된다. 계좌 소진이 있으면 부족을 알리고, **연금 계좌 잔액·지급 내역**에서 `기초 + 입금 + 운용 변동 − 지급 = 기말`을 확인할 수 있다. 부동산 관련 안내는 원본 자산 화면으로 연결된다.

## 계산 계약

- 현재 평가액을 올해의 기초 잔액으로 본다. 이미 지난 연도의 목돈 분배는 현재 잔액에 포함된 것으로 보고 다시 입금하지 않는다.
- 연 단위 모형에서 입금·지급 후 남은 잔액에 저장된 포트폴리오 운용 가정을 적용한다. 월별 거래일·수익률 경로를 복원한 모형은 아니다.
- IRP·연결 주식 계좌·원금 인출형 연금은 잔액 제한 대상이다. 연결 계좌가 없는 등록 지급형 연금과 국민연금은 외부 지급액 가정이며 투자 원금을 차감하지 않는다. 실제 계약의 지급 유형 확인은 필요하다.
- 국민연금을 포함해 원본의 지급 시작·종료 연도를 사용한다. 앱이 종료 연도를 임의로 무시하고 수명을 연장하지 않는다.
- 연금 계좌에 묶인 종목의 배당은 기본 모드 가계 배당 수입에 다시 더하지 않는다. 내부 운용 수익은 포트폴리오 가정을 따른다.
- 연금 시뮬 연동은 기존 저장 선택을 유지한다. 선택하지 않으면 수동 시뮬레이션 원천을 기본 수입에 추가하지 않는다. 연동 설정이 없는데 연동만 선택한 경우에는 대체 계산임을 알린다.
- 연금 세부 계산과 기본 분석을 비교할 때에는 같은 연도와 같은 연동 모드를 비교한다. 고급 월별 계획의 저장 스냅샷은 별도 모형이다.
- 취득/처분은 6월 1일 보유 상태와 연말 자산 상태를 구분한다. 현재 주식·연금 관리에서는 처분된 원천을 제외한다.
- 모든 보완은 읽기 전용 파생 계산이다. 사용자가 저장 버튼을 누르지 않으면 원본·과거 저장 분석을 다시 저장하거나 삭제하지 않는다.

## 세금 기준과 중요한 범위

기준 확인일은 2026-09-16이다. 과세기준일, 인별 공시가격 합산, 세율 구간과 재산세액 공제 구조는 국세청의 [종부세 안내](https://j.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7739&mi=2357), [인별 납세의무 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7738&mi=2352)를 확인했다. 농어촌특별세는 [납부 안내](https://j.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7734&mi=2352)를 참고했다.

현재 자동 보유세는 **일반 개인 주택의 추정 모델**이다. 공시가격은 기존 시가×75%, 재산세 과표비율은 60%, 도시지역분은 0.14% 가정이다. 인별 9억 일반공제를 사용하며, 단순히 ‘자가 거주’ 체크만으로 1세대1주택 특례 자격을 확정하지 않는다. 종부세는 인별 주택 수에 맞는 구간을 적용한다. 재산세 공제액도 추정한 공시가격·재산세를 사용하므로 실제 고지액과 다를 수 있다.

다음은 자동으로 확정하지 않는다: 정확한 공시가격, 멸실/주택 과세대상 전환의 법적 사실, 1세대1주택 및 공동명의 특례 신청, 합산배제, 연령·장기보유 공제, 세부담상한, 지역자원시설세, 토지·상가 세금, 취득세·양도세, 미래 법령 변경. 공사 중 세액이나 이런 사실관계는 임의로 만들어 채우지 않는다.

건강보험·연금/금융소득세도 기존 간이 추정식의 범위다. 이번에 부동산 시점·원천 명의·실제 예상 지급액의 연결을 고쳤지만 모든 공제·가입자 자격·보험료 부과 시차를 구현한 것은 아니다. 특히 **기본 등록 지급액 모드에서 연금소득세는 미산정임을 안내**한다. 표시 합계를 확정 세무 금액으로 사용하면 안 된다. 기존 법인 시뮬레이션의 전체 모형·가수금 시점도 이번 연금 원장 보완의 인수 범위가 아니다.

## 검증 방법

- `analysisReconciliation.test.ts`: 날짜 경계, 미입력/0 구분, 공동명의·인별 공제, 중복 연결, 소진 후 중단, 미래/과거 목돈, 명의별 수입, 건강보험 연결, 조회 기간 독립성, 수동 보유세 개시.
- `tools/check-local-app.cjs --analysis`: 가상 데이터의 기존 입력 수정·재계산 + 실제 부동산 편집 폼의 날짜·세액 저장/내보내기 + 연도 변경 + 소진 이후 수입 감소 + 데스크톱/모바일.
- `tools/check-local-app.cjs --backup <파일> --analysis`: 실제 백업을 격리 브라우저로 읽고 원본 테이블·원본 파일이 유지되는지 확인. 실제 금융정보는 촬영하거나 외부로 보내지 않는다.
- 전체 단위 테스트, 타입 검사, 배포 빌드와 기존 UI 회귀 검사를 함께 수행한다. 실행 결과는 최종 전달 메시지에 기록한다.
- 전체 단위 테스트 187개(14개 파일), 타입 검사와 배포 빌드 통과. 미저장 수익률 기본값 0도 회귀 검사에 포함한다. 기존 주식·고급 계획 저장/다시 열기 UI 회귀 검사와 실제 편집 폼을 통한 부동산 시점·세액 저장, 연금 소진 후 수입 감소 검사를 통과했다. 데스크톱/모바일 문서 너비 넘침과 브라우저 예외도 확인했다.
- 실제 백업의 분석 열람 전후 원본 테이블·파일 일치 확인. 임시 프로필은 파일 잠금으로 인한 정리 실패 후 정확한 해당 경로만 재시도하여 삭제 확인.

Docker나 새 의존성 설치는 없다. 실제 사용자 브라우저 데이터와 Git 원격 저장소를 자동 변경하지 않는다.
