# 06. 전체 화면 개편 시제품

## 개정 2 — 현재 자산 관리도 핵심 흐름

[07. 개정 명세](07-current-assets-and-retirement.md)에 따라 홈을 현재 자산 우선으로 변경하고 [주식 전문 관리](full-app.html#/stocks)를 추가했다. `자산 → 주식`도 이 전문 화면으로 연결된다. ‘자산 관리만 · 은퇴계획 미입력’ 예시를 추가해 총 7개 사용자 조합을 제공한다.

- [홈](full-app.html#/home): 현재 총자산·순자산·현금·구성을 우선 표시. 계획이 없으면 미래 전망만 보류한다.
- [주식 전체](full-app.html#/stocks) → [계좌](full-app.html#/stocks?asset=stock) → [종목](full-app.html#/stocks?asset=stock&position=demo-a): 수량·평단·현재가·평가액과 기준일을 확인한다.
- [평가 이력](full-app.html#/stocks?asset=stock&position=demo-a&tab=history), [배당](full-app.html#/stocks?asset=stock&position=demo-a&tab=dividend): 합성 관측과 수령 기록/미래 예상의 구분을 확인한다.
- 가상 시세 성공/일부 실패와 수량·평단 폼을 사용할 수 있다. 가격 갱신은 수량·평단·현금·수령 기록을 변경하지 않으며 상위 계좌 평가액으로 연결된다.

`current-assets.js`가 추가됐으므로 HTML만 복사하지 말고 폴더 전체를 전달한다. 실제 시세 연결·전체 배당 CRUD·과거 보정·영구 저장·정밀 투자성과를 구현한 것은 아니다. 시제품에서 생략된 기존 기능도 07의 AM/C 기준에 따라 실제 제품에서는 보존해야 한다.

아래 최초 제작 기록의 6개 예시·21개 이미지 수는 개정 전 기록이다. 개정본의 검사 기록은 문서 마지막에 별도로 정리한다.

이전 `prototype.html`은 분석 화면 일부만 보여주었다. 이번 `full-app.html`은 **홈·자산·계획·분석·설정과 상세 화면을 연결한 별도 전체 앱 시제품**이다. 원래 제품의 코드를 교체하거나 개인 데이터를 이전한 것은 아니다.

## 먼저 보는 방법

1. [전체 화면 이미지 모음](screenshots.html)에서 페이지별 모양을 나란히 비교한다. 이미지 선택 시 원본 크기로 열린다.
2. [전체 앱 직접 사용](full-app.html#/guide)의 화면 안내에서 원하는 페이지를 연다. 설치·서버 실행은 필요 없다.
3. 메뉴를 따라 `자산 → 자산 상세 → 입력 수정`, `계획 → 생활비 수정`, `분석 → 연도·월별 → 연도 선택 → 월 선택` 순서로 확인한다.
4. 상단 ‘사용자 예시’를 바꾸면 부동산 없음·일반 자가·임대·재건축·은퇴한 1인·미입력 상태를 비교할 수 있다.

페이지 상단에도 기존 위치와 개편 위치를 표시했다. 실물·기타 자산도 자산 추가/상세/편집으로 확인할 수 있다. 보유하지 않은 유형의 직접 링크에는 해당 유형의 빈 상태와 추가 버튼이 나온다.

## 실제로 동작하는 범위

- 여섯 자산 유형 추가·이름/금액/명의 수정. 부동산 상태에 따라 입력 필드가 달라진다.
- 생활비·급여·은퇴 시점·연금 지급 시작·대출 이자·임대 수입의 예시 편집.
- 재건축 준공·분담금·임시 거주비·임대 시작의 연결.
- 외부 목돈·일회성 지출 일정 추가·수정.
- 같은 입력을 쓰는 2030~2040년 단순 월별 계산과 연간 합계.
- IRP 계좌 지급 한도, 외부 연금과 원금 인출 구분, 현금 미충당액 별도 표시.
- 연도·시나리오 선택, 숫자 상세, 연도→월→거래→자산 이동.
- 법인 자금의 세금 전 단순 관계 미리보기. 기본 은퇴 전망에는 합산하지 않음.
- 수정한 가상 예시 JSON 내보내기와 복원 과정의 화면 미리보기.

## 시제품의 한계

데이터는 열린 창의 메모리에만 보관한다. 새로고침·사용자 예시 전환·초기화 시 바꾼 예시는 사라진다. 중요한 검토 예시는 설정에서 JSON으로 내보낼 수 있지만 이 시제품에서 재가져오기는 제공하지 않는다.

세금·건보는 입력한 고정 금액이며 세법을 계산하지 않는다. 세금의 12월 납부는 예시 선택이며 실제 법정 일정이 아니다. 물가·시장가격 상승·자동 매각·새 차입은 모델링하지 않는다. 현재 시가와 부채는 현재 자산 표에 표시하며, 미래 순자산 전체 추이는 구현하지 않았다. 국민연금 지급권의 월액을 현재 자산 평가액에 더하지 않는다.

대출 잔액·보증금은 현재 부채로 보여주고, 대출 이자·임대 수입을 현금 예시에 연결한다. 실제 원리금 상환표·보증금 계약 정산·세무 규칙은 통합 구현에서 추가할 범위다. 평가 이력은 예시 초기 값과 이 창에서 변경한 이전 값만 표시하며, 시세나 과거 배당 입금 실적을 만들어 보여주지 않는다.

## 확인 기록

추가 설치 없이 기존 Node와 Chrome을 사용했다. 원래 앱의 IndexedDB와 브라우저 프로필에는 접근하지 않고 별도 임시 프로필에서 확인했다.

- 6개 사용자 조합에서 14개 화면 렌더링 함수, 총 84개 결과를 확인했다.
- 기본안·생활비 증가안·해당 시 준공 지연안의 월별 원장 1,452개 행에서 현금 보존식과 잔액을 검사했다.
- 실제 브라우저에서 데스크톱 12개 경로, 390px 모바일 주요 5개 페이지, 상세와 빈 상태를 검사하고 이미지를 저장했다.
- 생활비 변경의 재계산, 준공 변경의 연결 일정 이동, 비재건축 사용자 노출, 연도→월→원천 상세를 확인했다.
- 여섯 자산 유형의 실제 폼 추가, 목돈 일정 추가의 현금 반영, 법인 자금 구조 미리보기까지 브라우저 submit으로 확인했다. 실행 중 브라우저 예외는 0건이었다.
- 이미지 21개를 저장했으며 문서·HTML의 로컬 참조 101개에 누락 파일이 없음을 확인했다.
- 실제 개인 데이터·기존 앱 테스트·세법 정확성·실기기 터치와 스크린리더 검증은 별도 작업이다.

브라우저 확인 보조 스크립트는 [check-full-app.cjs](check-full-app.cjs)다. 로컬 Chrome의 경로가 고정돼 있으므로 다른 환경에서는 경로를 조정해야 한다. 생성된 화면은 [이미지 모음](screenshots.html)에서 확인한다.

## 개정 2 및 교차 점검 후 확인 기록

- 현재 자산 관리만 사용하는 예시를 포함한 7개 조합에서 49개 주요 렌더 결과를 검사했다.
- 단순 월 원장 1,452행의 현금 보존식·현금/IRP 잔액을 검사했다.
- 가상 시세 전체/부분 성공, 동일 가격 재조회, 현금·평단·실제 수령 예시 기록 불변, 상위 계좌 합계를 검사했다.
- 은퇴 미입력의 계획·가정·설정 표시와 은퇴 사건 미생성, 계획 없이 가구·명의 설정/배우자 계좌 등록, 주식 필터→전체 복귀, 지연 시나리오→자산 현금 상세 일치를 회귀 검사에 추가했다.
- 설치된 Chrome의 별도 임시 프로필로 데스크톱 17개 경로, 모바일 주요 10개 화면을 검사했다. 기존 계획 수정·준공 일정·6유형 추가·월별 상세 검사도 유지했다. 실행 중 브라우저 예외는 0건이었다.
- 화면 이미지 32개를 생성했다. 문서·HTML의 로컬 참조에 누락 파일이 없는지 검사했다.

검사 도구: [계산 경계·문서 참조](check-current-assets.cjs), [브라우저 동작·캡처](check-full-app.cjs). 교차 점검 해석과 남은 실제 제품 범위는 [08](08-cross-review.md)을 참조한다. 이 결과는 시제품 검증이며 AM/C 전체 제품 검수나 세무 정확성 검증이 아니다.
