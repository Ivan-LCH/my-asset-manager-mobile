# 04. 구현 계획과 인수 기준

개정 2: [07. 현재 자산 관리·은퇴설계](07-current-assets-and-retirement.md)의 R0 현재 기능 기준선, AM-01~AM-10 기능 보존 및 C01~C29 인수 기준을 추가 적용한다. 아래 최초 계획의 은퇴 기능뿐 아니라 독립적인 현재 자산 관리도 출시 검수 범위다.

추가 결정: 실제 적용 묶음과 순서는 [05의 R1~R6](05-implementation-spec.md)을 우선한다. 아래 A01~A30은 유지하고 05의 B01~B24, G01~G06을 추가한다. 재건축 이전에 부동산 없는 사용자의 공통 은퇴 원장을 완성한다.

## 1. 진행 방식

전면 재작성보다 기존 PWA를 유지하면서 계산과 화면을 작은 범위로 교체한다. 먼저 현재 결과를 무조건 정답으로 고정하지 말고, 알려진 결함을 재현하는 사례와 올바른 기대값을 구분한다. 일정은 세무 지원 범위와 인력 확인 전 확정하지 않는다. 아래 완료 조건을 통과한 단위로 배포한다.

| 단계 | 구현 범위 | 대상 코드 / 산출물 | 완료 조건 |
|---|---|---|---|
| 0. 신뢰성 복구 | F01 국민연금 중복, F02 보유세 설정 유실, F03 지급 초과, F08 세금 중복을 먼저 해결. 월 여유의 의미 명시 | pensionSim, retirementPlan, RetirementPrepPage, accountSim, retirementCashflow, 회귀 사례 | 해당 재현 사례의 올바른 기대값 통과, 다른 설정 보존 |
| 1. 데이터 계약 | 사람 ID·계좌·평가 기준일·부채·원천 참조·revision·규칙 버전 정의 | domain schemas, snapshot builder, 저장소 어댑터, migration preview | 기존 자산·부채 합계 보존, 중복 연결 후보 보고, 누락 사실을 추정 확정하지 않음 |
| 2. 재건축 기능 연결 | 공사 중 자산 1건, 준공·분담금·임대·대출·세금 입력, 기본/지연안, 월 원장 | event resolver, property module, deterministic ledger, 간단한 분석 상세 | 입력 하나의 변경이 모든 결과에 전파되고 월별 잔액 대사 통과 |
| 3. 개인·가구 은퇴 | 연금 지급권/계좌 인출, 소유자별 소득, 생활비 구간·물가, 예금·투자·인출 정책, 보험 자격 | 통합 engine, 규칙 모듈, 영향 설명 | 수입=실제 지급, 인출=계좌 감소, 최초 부족월 검증 |
| 4. UX 전환 | 홈·자산·계획·분석, 클릭 상세, 시나리오, 저장 상태, 모바일 접근성 | 기존 화면 점진 교체, URL 상태, 결과 selector | 핵심 사용 과제를 도움 없이 수행, 숫자·상세·내보내기 일치 |
| 5. 고급 확장 | 법인 비교의 공통 원장 연결, 더 많은 부동산 거래, 민감도·확률분석 | 별도 전략 모듈·검증 데이터 | 법인과 가구 현금 중복 제거, 가정/지원 범위 검증 |

단계 2의 보유세는 검증된 범위만 자동 계산한다. 지원하지 않는 재건축 세무는 금액·납부일·근거가 있는 수동 예상액으로 시나리오를 완성할 수 있게 한다. 완전한 세무 엔진을 기다리며 전체 은퇴 기능을 막을 필요는 없다.

## 3. 기존 데이터 이전

이전은 자동으로 사실을 만들어 채우는 작업이 아니다. 원본 백업 → 형식 검사 → 변환 미리보기 → 적용 → 검증의 순서를 따른다.

| 기존 입력 | 이전 방법 | 사용자 확인이 필요한 부분 |
|---|---|---|
| currentValue | 현재 평가액 + 기준일 정보 보존 | 기준일을 알 수 없으면 ‘기준일 미확인’ |
| futureValue / futureYear | 예정 가치 변경과 연 정밀도 사건으로 이전 | 준공/사용승인/입주 중 어떤 의미였는지, 정확한 날짜 |
| disposalDate | 기존 데이터의 처분 기록으로 보존 | 미래 날짜이면 계획인지 입력 오류인지 확인. 과거 매각대금은 현재 현금에 다시 넣지 않음 |
| loanAmount | 현재 부채 잔액 | 금리·만기·상환 방식 미입력 표시 |
| tenantDeposit | 의미상 임차인에게 받은 보증금 부채 후보 | 임대인/임차인 역할 확인 후 이전 |
| PENSION + linkedStockId | 지급권/계좌 관계 후보, 중복 평가 검사 | 같은 경제적 잔액인지, 계좌 ID 연결 |
| PensionSource.principal | 기존 값과 자산 평가액 모두 보존 | 차이가 나면 사용자의 가정인지 오래된 복사본인지 확인 |
| lumpsum + allocations | 원천 사건 ID + 날짜 연결 계좌 이전 | receiveYear만 있으면 지급월 미확정, 분배 합계 초과 검사 |
| holdingTax 수동값 | 연간 수동 예상액과 적용기간 보존 | 납부월 미정, 자동 추정으로 변경하지 않음 |
| husband/wife ownership | 본인·배우자 Person ID와 지분 이력 | 1인 가구의 가상 배우자 지분 자동 재배분 금지 |

원본/변환 레코드 ID 대응표, 이전 버전, 이전 시각, 오류·확인 필요 목록을 보관한다. migration은 반복 실행해도 중복 데이터를 만들지 않아야 한다. 변환·검증·활성 버전 전환은 원자적으로 수행한다. 실패 시 원본을 계속 사용할 수 있어야 한다.

백업에는 형식 버전, 테이블 목록, record count, 원천 revision, 내보낸 시각, 무결성 확인값을 넣는다. 확인값은 손상 탐지용이며 작성자 인증을 보장하지 않는다. 비밀번호 암호화는 별도 선택 기능으로 설계하고 키를 같은 파일에 저장하지 않는다.

모든 월에 현금·부채·계좌 보존식을 검사하고, 연간 합계는 월 결과 집계로만 만든다. 세법 테스트는 구현 식을 복사한 기대값을 피한다. 공식 모의계산·검증된 고지 사례·검토자가 독립 계산한 합성 사례에 적용연도와 사실관계를 붙인다. 단순 세율 일부가 맞는 것으로 전체 세액을 인증하지 않는다.

## 5. 사용성 확인

첫 대상은 자산을 직접 입력하는 은퇴 준비자 5명 내외로 시작한다. 다음 과제에 걸린 시간, 잘못 누른 횟수, 도움 요청, 숫자 의미에 대한 답변을 기록한다. 숫자는 제품 목표이며 측정 결과가 아니다.

- 재건축 주택을 등록하고 준공·추가 납부·임대 시작을 연결: 기본 정보가 준비된 조건에서 5분 이내 목표.
- 2031년 세금 증가 이유를 특정 자산·사건까지 찾기: 1분 이내 목표.
- 준공 1년 지연안과 기본안의 최저 현금 차이를 설명: 2분 이내 목표.
- 생활비를 수정하고 저장·분석 반영 상태 확인: 미저장 값을 저장된 결과로 오인 0건 목표.
- 월 여유와 기말 현금의 차이를 설명: 목돈·세금·계좌 인출을 구분할 수 있어야 함.

대표 Android·iOS 기기와 데스크톱에서 온라인/오프라인, 앱 업데이트, 새로고침, 백업 복원을 확인한다. 단순 시나리오 재계산은 기준 기기에서 1초 이내를 초기 목표로 두고 실측한다. 초과하면 진행 상태와 취소·이전 결과를 제공한다.

## 6. 배포·완료 기준

새 엔진은 초기에는 기존 결과와 함께 비교하되, 두 결과 중 어느 것이 사용자 계획에 적용되는지 명확히 한다. 기존 결과와 차이가 난다는 이유만으로 회귀 실패로 판단하지 않는다. 알려진 오류 교정, 규칙 변경, 모델 범위 차이로 원인을 분류한다.

배포 전 데이터 보존·핵심 계산·사용 흐름 검증을 통과하고 지원 세무 범위를 화면에 표시한다. 롤백 시 새 형식 데이터가 구버전 코드에 의해 덮어쓰이지 않도록 DB 버전 호환성을 검사한다. 데이터 이전 전 백업과 결과 기준 revision을 보존한다.

사용자가 입력한 현재 자산과 한 건의 재건축 계획을 기준으로, 사건을 옮기면 관련 수입·지출·세금·잔액이 동시에 바뀌고, 어느 숫자든 원천까지 추적되며, 이를 테스트와 원장으로 확인할 수 있을 때 첫 재설계가 완료된 것으로 본다.
